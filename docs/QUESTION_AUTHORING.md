# 문제·해설 작성 및 편향 검사 기준

이 기준은 신규 생성, 수정, 회차 조합, 선지 재배치에 모두 적용한다. 자동 검사는 편향을 발견하는 장치이며 문항의 정확성과 타당성을 보장하는 통계적 증명은 아니다.

## 1. 정답과 오답의 내용

- 객관식은 정답 1개, 선지 4개. 순서·가정·자료형·인덱스·그래프 방향·이웃 방문 순서 등 답에 영향을 주는 전제를 적는다.
- 오답은 실제로 혼동하기 쉬운 개념으로 만든다. 터무니없는 오답이나 정답만 전문적이고 구체적인 구성을 피한다.
- 문법, 문장 구조, 조건 수, 설명 깊이를 가능한 한 맞춘다. 정답에만 괄호·예시·단서·예외 조항을 붙이지 않는다.
- `항상`, `무조건`, `오직` 같은 단정 표현이 오답에만 반복되거나 지문의 용어가 정답에만 그대로 등장하지 않는지 검토한다.
- `위의 모두`, `①과 ③`처럼 선택지 위치에 종속되는 문구를 쓰지 않는다.
- 시간 복잡도 문항은 빅오 표기법만 쓰고 주어진 코드나 절차의 복잡도를 측정하는 문제만 낸다. Θ와 Ω, 상한과 하한의 정의처럼 표기법 이론을 묻지 않는다. 빅오는 더 큰 차수도 형식상 성립하므로 "가능한 가장 작은 차수로 답한다"를 문제에 넣어 정답을 하나로 정한다.
- 한 회차 안에서 같은 개념을 같은 방식으로 묻는 문항을 두지 않는다. 형식(객관식과 단답형)만 다르고 답이 겹치는 문항도 중복으로 본다.
- 복잡도는 최악/평균/상환 분석과 자료구조 구현 조건을 구분한다. BFS/DFS 순서를 묻는 문제는 시작점과 이웃 처리 순서를 명시한다.

## 2. 정답 번호 배치 — 필수 통과

기본은 4지선다이며 다음 수치는 이 형식의 프로젝트 편집 기준이다.

| 검사 단위 | 기준 |
| --- | --- |
| 과평 1회 21개 | 각 정답 번호 4~7개 |
| 기본 3회 전체 63개 | 각 정답 번호 14~18개 |
| 연속 정답 | 같은 번호 3개 이상 연속 금지 |
| 단순 반복 | ABABAB 형태 금지. 길이 3~4인 동일 블록이 연속 두 번 반복되면 금지 |
| 문항·정답 연결 | 정답 choiceId가 존재하고, 4개 choiceId가 고유하며, 각 선지 해설이 존재해야 함 |

검사 순서는 실제 응시 화면의 객관식 순서다. 여러 파트 사이의 비객관식 문항은 제외하고 객관식 정답열을 만든다. 기본 회차와 새로 섞은 회차 모두 검사한다. 번호의 대칭성을 유지하고 매번 `1,2,3,4`를 반복하거나 특정 번호를 먼저 채우는 생성기를 쓰지 않는다.

일반 주제 연습은 N≥12일 때 번호별 빈도가 `floor(N/4)-1` 이상 `ceil(N/4)+1` 이하가 되게 한다. N<12는 정답 비율 기준을 강제하지 않고 연속·반복 규칙과 빈도만 확인한다. 문제 전체 수가 63개와 다르면 전체 기준도 일반 N 규칙을 사용한다.

숫자·시간·복잡도처럼 자연스러운 정렬이 중요한 선택지는 `orderLocked`로 명시하고 문항 순서 조정으로 분포를 맞춘다. 조건을 충족할 수 없으면 실패를 반환하고 검수한 기본 배치를 사용한다. 위반한 배치를 조용히 허용하지 않는다.

## 3. 선지 길이·구체성 — 검토가 필요한 신호

길이 계산은 Markdown 표식만 제거한 표시 텍스트를 Unicode NFC로 정규화하고 공백을 하나로 합친 뒤 Unicode 코드포인트 수를 센다. 한글·수식·코드를 지우지 않는다. 코드 선지는 코드 줄 수도 함께 보고한다.

자동 보고서에 포함할 지표:

1. 각 문항의 정답 길이 / 전체 선지 길이 중앙값. 1.35 초과 또는 0.65 미만이면 경고. 중앙값 0은 빈 선지 구조 오류다.
2. 각 문항의 최대 길이 / 최소 길이. 2.0 초과이면 경고.
3. 정답이 유일한 최장/최단 선지인 문항 수. 동률인 경우 유일 최장/최단으로 세지 않는다.
4. 동률 가중 최장 비율: 최장 선지 수가 k이고 정답이 그중 하나면 1/k, 아니면 0을 부여해 평균을 낸다. 최단도 동일하게 계산한다.
5. 회차 및 전체에서 가중 최장/최단 비율이 0.15~0.35 밖이면 경고. N<20은 판정하지 않고 수치와 작은 표본 표시만 낸다.
6. 회차 및 전체의 평균 정답 길이 / 평균 오답 길이가 0.85~1.15 밖이면 경고. N<20은 수치만 보고한다.

경고는 의미 검토 없이 통과시키지 않는다. 문장을 고치거나, 수식·코드 구조상 필요한 차이라면 트랙 폴더의 `authoring-reviews.json`에 문항 ID, revision, 검사 코드, 이유, 검토 주체, 검토일을 기록한다. 집계 경고는 관련 회차 ID와 콘텐츠 해시를 기록한다. 문항 또는 해당 집계 콘텐츠가 바뀌면 검토를 만료시킨다.

경고를 없애기 위한 의미 없는 문구 추가·오답 늘리기를 금지한다. 자동 수치가 정상이더라도 정답만 자세한 조건을 갖거나 지문을 반복하면 수정한다. 선지 높이 통일은 화면상 크기 단서를 줄이는 보조 수단이다.

## 4. 해설과 검증

- 객관식: 정답 근거 → 풀이/추적 과정 → 각 오답이 틀린 이유 → 흔한 실수.
- 단답: 모범답안·허용 표기·문항별 정규화 규칙·근거. 출력/숫자 문제는 직접 검산한다.
- 서술: 모범답안과 독립적으로 채점 가능한 기준·부분점수·핵심 누락 예시.
- 구현: 접근, 자료구조, 순서도에 해당하는 단계 설명, Java 기준 풀이, 시간/공간 복잡도, 입출력 예시, 경계·반례, 자기채점 체크리스트.
- 순열은 visited 복원·중복, 격자는 이동 불가 시 방향·경계·장애물, 충돌은 반 단위 시간·다중 동시 충돌·동시 갱신을 확인한다.
- 작성 후 정답을 가린 상태로 다시 풀어 정답의 유일성과 해설 일치를 검토한다. 코드 예시는 명시한 Java 버전에서 실행한다.

구현될 표준 명령:

```text

python scripts/verify_code_answers.py
```

스키마/정답 연결 오류, 범위·문항 수 오류, 번호 배치 위반, 미검토 길이 경고는 CI 실패로 처리한다. PR 템플릿은 위 검사 결과와 해설 검토를 필수 항목으로 둔다. 이 문서의 기준을 바꿀 때는 근거와 영향을 명시하고 기존 전체 문제은행을 다시 검사한다.

## 6. 한국어 표시와 문장 품질

- 모든 원고와 화면 파일은 UTF-8로 저장하고 HTML에 charset과 lang=ko를 명시한다.
- 한글은 단어 단위로 줄바꿈하고 긴 URL과 코드는 별도로 처리한다. 제목을 맞추려는 강제 br을 넣지 않는다.
- 짧은 표제는 불필요한 마침표 없이 쓰고 설명은 자연스러운 문장으로 작성한다.
- 쉼표와 가운뎃점으로 키워드를 길게 나열하지 않는다. 반복 문장부호와 깨진 문자는 검증 오류로 처리한다.
- 코드와 수식의 필수 기호는 보존한다. 360px 모바일 화면과 데스크톱에서 줄바꿈과 글자 잘림을 직접 확인한다.
- 코드 블록은 표준 Java 형식으로 쓴다. 들여쓰기는 4칸이고 `if`, `for`, `while`의 본문이 한 줄이어도 중괄호를 쓴다. 한 줄에 한 문장만 두고 연산자 앞뒤에 공백을 둔다.
- 복잡도 표기, 점화식, 부등식, 분수처럼 수식은 LaTeX로 쓴다. 인라인은 `$\Theta(N \log N)$`처럼 `$`로 감싼다. 문장 속 단독 변수 N은 일반 글자로 둔다. 코드 식은 수식이 아니라 백틱 코드로 쓴다.
- 트리와 그래프는 설명만 쓰지 않고 도식을 넣는다. 이진 트리는 ` ```tree ` 블록에 1번 인덱스 레벨 순서 배열을 쓰고 빈 자리는 `-`로 둔다. 배열 인덱스를 보여 줄 때는 첫 줄에 `indexed`를 쓴다. 그래프는 ` ```graph ` 블록에 한 줄에 간선 하나씩 `A - B`(무방향) 또는 `A -> B`(방향)로 쓰고, 부모를 가리키는 서로소 집합은 첫 줄에 `direction: up`을 쓴다. 문장 속에서 트리를 `A→B→C`처럼 화살표로 나열하지 않는다.
- 문항 제목은 해설에서 "주제"로만 보이므로 무엇을 다루는 문제인지 드러나게 쓴다. 예: "무방향 차수 합"이 아니라 "무방향 그래프 차수의 합". 구현형 제목은 풀이 중에도 보인다.
- 사전순 다음 순열은 처음 등장할 때 "사전순 다음 순열(Next Permutation)"로 쓴다.
- 문제는 채점 기준이 분명한 표현으로 쓴다. "타이트한 차수"처럼 풀이자마다 해석이 달라질 수 있는 용어 대신 "$\Theta$ 표기로 나타내면"처럼 표기법을 지정한다.

## 7. 프론트엔드 트랙

프론트엔드 문항은 `exam.json`에 `"track": "frontend"`를 쓰고 `source/frontend/scope-frontend.json`의 범위를 따른다. 1~6절은 그대로 적용하며 아래 내용만 다르다.

- 코드 블록은 `html`, `css`, `js` 언어 표시를 쓴다. 들여쓰기는 2칸이고 세미콜론과 작은따옴표를 쓰며 `if`, `for`의 본문이 한 줄이어도 중괄호를 쓴다. Java의 4칸 규칙은 프론트엔드에 적용하지 않는다.
- 코드의 한 줄은 공백 포함 38자 이하로 쓴다. 360px 모바일 화면에서 코드 상자 안쪽 폭은 약 252px이고 기본 글꼴이 없는 환경의 고정폭 글꼴(글자당 약 6.6px)에서도 가로 스크롤 없이 보여야 하며 긴 줄은 줄바꿈해서 쓴다. `validate_questions.py`가 길이를 검사한다.
- 문항 메타데이터의 `topics`에는 대주제 ID 하나를 쓰고 `group`도 같은 값으로 쓴다. 세부 주제는 `tags`에 쓴다. 3회를 합쳐 모든 세부 주제가 한 번 이상 나와야 한다. 복습 노트에서 가져온 문항은 `sourceRefs`에 노트의 절을 함께 적고 문구를 그대로 옮기지 않는다. Bootstrap 문항은 `package.json`에 고정한 버전(5.3.3)의 CSS로 실행해 확인한다.
- 브라우저나 버전에 따라 결과가 달라지는 동작은 출제하지 않는다. 출력과 계산 문제는 실제 실행해 확인하며 방법은 `scripts/verify_frontend_answers.mjs`에 기록한다. 이 검증은 해당 스크립트의 케이스 파일이 문항 ID와 revision을 가리켜야 한다.
- 정답이 둘이 되는 표현을 피한다. Falsy 값은 명세상 8가지(`0n`과 `-0` 포함)이므로 개수가 아니라 개별 값의 판별을 묻는다.
- 주제별 연습 세트(같은 대주제의 문항을 회차 순서로 모은 세트)도 2절의 일반 N 규칙으로 검사한다.

## 8. AI 역량검사 트랙

AI 역량검사 문항은 `exam.json`에 `"track": "ai"`를 쓰고 회차 종류(`kind`)는 필기 `written`, 실기 `practical`이다. 범위는 `source/AI역량검사/scope-ai.json`을 따르며 1~6절을 그대로 적용한다. 다만 길이 편향 기준(3절)은 필기 100문항 회차에서 가중 최장·최단 비율 0.15~0.35 안이어야 하므로 모든 선지를 서로 비슷한 길이와 구체성으로 쓴다.

- 필기형은 객관식 100문항이다. 정답 번호는 회차 전체에서 번호별 24~26개이고 대주제별 연습 세트는 2절의 일반 N 규칙을 따른다.
- 필기 문항은 강의 개념을 묻는다. 논문 연도와 저자, 벤치마크 점수, 강사 정보처럼 외우기만 하는 내용은 묻지 않는다. 상황 판단 문항은 지문에 판단 조건(자료 양, 자원, 지연, 갱신 주기)을 적고 강의 내용으로 정답 근거를 댄다.
- 코드는 `python` 언어 표시를 쓰고 들여쓰기는 4칸이다. 한 줄은 38자 이하로 쓰고 긴 호출은 괄호 안에서 4칸 들여써 줄바꿈한다. `validate_questions.py`가 검사한다.
- 계산과 코드 출력과 텐서 모양은 `requirements-ai.txt`의 버전으로 실행해 확인한다. 버전에 따라 기본값이나 결과가 달라지는 동작은 묻지 않는다. 필기 문항의 실행 코드는 `ai-written-checks.json`에, 실행할 수 없는 문항의 재풀이 기록은 `ai-reviews.json`에 문항 ID와 revision을 가리켜 둔다.
- 실기형은 8문항이고 소문항 배점의 합이 문항 배점이며 8문항의 합계가 100점이다. 각 문항은 서로 독립이고 같은 문항 안의 소문항만 앞의 결과를 쓸 수 있다.
- 실기 문항의 본문에는 준비 코드(첫 번째 `python` 블록)와 답안 템플릿(두 번째 `python` 블록)을 차례로 둔다. 메타데이터의 `checks`에 숨은 검사(assert 문)를 두고 `modelAnswer`의 코드 블록은 템플릿을 대체하는 완성 코드로 쓴다. `verify_ai_answers.py`가 모범답안은 통과하고 빈 템플릿은 실패하는지 확인한다.
- 실기 데이터는 scikit-learn에 포함된 자료나 코드로 만든 자료만 쓴다. 인터넷과 생성형 AI 호출과 외부 가중치 내려받기가 필요한 과제는 내지 않는다. 정확도 수치는 정답 조건으로 쓰지 않는다.
- 실기 서술 소문항은 모범답안과 별도로 핵심어와 배점을 `rubric`에 둔다.
- 강의 원본(PDF, 슬라이드 이미지, 전사본, 실기 예시)은 저장소에 올리지 않는다. 문항의 `sourceRefs`에는 강의 파일 이름과 해당 절을 적는다.

## 9. ADsP 트랙

ADsP 문항은 `exam.json`에 `"track": "adsp"`를 쓰고 회차 종류(`kind`)는 `subject`다. 범위는 `source/adsp/scope-adsp.json`을 따르며 1~6절을 그대로 적용한다.

- 회차는 객관식 50문항이다. 1과목 데이터 이해 10, 2과목 데이터 분석 기획 10, 3과목 데이터 분석 30으로 나누고 단답형과 서술형은 두지 않는다. 대주제별 문항 수는 scope의 `groups`가 정한다.
- 정답 번호는 한 회차에서 번호별 11~14개, 3회를 합친 150문항에서 번호별 36~39개로 맞춘다(2절의 일반 N 규칙). 같은 번호 3연속과 반복 패턴은 회차 안에서 금지한다. 주제별 연습 세트도 같은 규칙으로 검사한다.
- 길이 편향은 3절을 그대로 적용한다. 회차가 50문항이므로 가중 최장·최단 비율 0.15~0.35와 정답/오답 평균 길이 비 0.85~1.15를 회차마다 지켜야 한다. 숫자나 짧은 용어만 있는 선지는 길이가 같도록 쓴다.
- 문항 메타데이터의 `topics`와 `group`에는 대주제 ID 하나를 쓰고 세부 주제는 `tags`에 쓴다. 3회를 합쳐 모든 태그가 한 번 이상 나와야 한다.
- 요약 노트는 개인 소장 자료이며 저작권 보호 대상이다. 개념과 사실만 쓰고 노트의 문장, 표, 예제 수치, 비유를 옮기지 않는다. 상황과 숫자는 새로 만든다. `sourceRefs`에는 노트의 과목과 절을 적고 파일 이름은 적지 않는다. 노트 PDF는 `private/`에 두고 커밋하지 않는다.
- 교재마다 다르게 쓰이는 값(데이터 분할 비율, t분포를 쓰는 표본 수 기준 등)은 정답의 근거로 쓰지 않는다. 정의나 수식으로 정답이 하나로 정해지는 내용만 출제하고, 노트에 부정확한 설명이 있으면 그대로 따르지 않고 올바른 정의로 쓴다. p-값은 "귀무가설이 참일 확률"이 아니라 귀무가설 아래에서 관측 결과 이상으로 극단적인 값이 나올 확률로 다룬다.
- R 출력 화면처럼 외부 도구의 출력은 옮기지 않고 필요한 수치를 문장으로 제시한다. 수식은 6절의 LaTeX 규칙을 따른다.
- 계산 문항은 `scripts/verify_adsp_answers.py`가 `source/adsp/adsp-checks.json`의 코드를 실행해 출력값이 정답 선지에 들어 있는지 확인한다. 계산하지 않는 문항은 `source/adsp/adsp-reviews.json`에 문항 ID와 revision을 가리키는 재풀이 기록을 둔다. 코드는 표준 라이브러리만 쓴다.
