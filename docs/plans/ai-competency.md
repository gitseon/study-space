# AI 역량검사 모의고사 제작 계획

작성일: 2026-10-15. 상태: 9절의 결정에 따라 필기 1회와 실기 1회까지 구현했다. 나머지 회차는 보류한다.

## 1. 목표

- 홈 화면에 `AI 역량검사` 트랙 버튼을 추가하고 필기 검정형과 실기 검정형 모의고사를 제공한다.
- 시험 범위의 개념 요약 노트를 `AI 개념` 버튼으로 연다. 원고는 `source/AI역량검사/AI역량 개념 요약노트.md`이며 이번에 함께 작성했다.
- 공개 범위와 강의 자료를 바탕으로 직접 만든 연습 문제이며 실제 출제를 보장하지 않는다.

## 2. 시험 규정 요약

원본은 `AI역검안내-1.jpg`, `AI역검안내-2.jpg`(FAQ), `AI역량검사소스.md`(설명회 전사)이다.

| 항목 | 필기 검정 | 실기 검정 |
| --- | --- | --- |
| 일시 | 10/16(금) 13:45~15:45 | 10/16(금) 16:00~18:00 |
| 형식 | 객관식 100문항 | 코딩형과 서술형 8문항 |
| 환경 | 학사사이트 화면에서만 응시 | Python 3.11 이상과 JupyterLab, 사전 설치 환경 |
| 제출 | 화면의 제출 버튼, 재제출 불가 | 답안과 실행 결과가 남은 노트북 파일 하나 |
| 금지 | 생성형 AI와 인터넷, 외부 자료 | 같음. 함께 제공된 참고자료만 허용 |

- 출제 분야는 다섯 개다. AI와 기계학습, 자연어 처리 기본과 심화, 딥러닝과 영상 모델, LangChain과 Agent 모델, 리소스 최적화.
- 범위는 AI 강의 II의 이론과 실습 전체이며 특정 챕터에 몰리지 않는다. 필기도 실습 내용을 포함한다.
- 문항은 암기보다 이해를 묻는다. 개념 이해, 상황에 맞는 기술 선택, 코드 구현, 결과 해석의 네 역량을 본다.
- 난이도는 기존 과목평가와 월말평가보다 높다. 두 검정의 합산 점수로 레벨 1과 2를 주며 한쪽이라도 최소 점수에 못 미치면 과락이다.
- 실기 예시(`AI 역량 평가_실기검정_Questions_sample.md`)는 8문항 100점, 120분이다. 문항마다 배점이 붙은 (a)(b)(c) 소문항이 있고 "실행만 하세요" 준비 셀과 "작성하세요" 답안 셀과 확인 셀로 이루어진다. 답은 정해진 변수 이름에 저장한다. 정확도 도달은 정답 조건이 아니고 요구한 처리 과정을 수행하는지 본다.

### 3-2. 범위에 미치는 영향

- `ai-4-1_LangChain.md`에는 LangChain 강의가 빠져 있다. 같은 강의의 PDF 쪽으로 보충해 범위에 넣었다. 공식 출제 분야 4번이 "LangChain, Agent 모델"이므로 그대로 두면 분야 하나가 비게 된다.
- 1-2의 역전파와 MLP 실습은 실기 예시의 학습 루프와 직접 연결된다.
- 공식 출제 분야 2번의 "심화"에 해당하는 별도 강의는 폴더에 없다. 4-1의 사후학습과 RAG가 심화를 대신하는지는 확인하지 못했다.
- 3-2, 4-2, 5-2는 공식 범위("AI 강의 II 전체")에는 들어갈 가능성이 높지만 사용자가 정한 범위(md)에는 없다. 사용자 결정에 따라 범위에서 제외했고 개념 노트에도 넣지 않았다.

### 3-3. 저장소 상태에서 먼저 고칠 것 (처리 완료)

- 처리 결과: `TRACKS`에 트랙별 폴더를 두어 빌드를 복구했고 기존 `data/`의 회차 내용은 바뀌지 않았다(manifest의 회차 순서만 바뀜). 원인은 다음과 같다. 원고를 `source/dsAlgo/`와 `source/frontend/`로 옮긴 변경 때문에 지금 `python scripts/build_data.py`가 "No exam manuscripts found"로 실패한다. `build_data.py`는 `source/*/exam.json`만 찾고 범위 파일과 노트도 `source/` 바로 아래에서 읽는다. `audit_bias.py`(`source/authoring-reviews.json`)와 `verify_frontend_answers.mjs`(`source/frontend-reviews.json`)의 경로도 깨졌다.
- `source/AI역량검사/`의 원본(PDF 457MB, 이미지 759MB, 전사본, 예시 노트북)은 아직 커밋되지 않았다. 강의 자료 재배포 문제와 용량 문제가 있어 `.gitignore`에 넣는다. 공개 저장소에는 직접 쓴 범위 파일과 문항과 요약 노트만 둔다.
- `모의평가_생성계획.md`는 다른 시험 자료이므로 이 트랙의 원고로 쓰지 않는다. 커밋 여부는 사용자가 정한다.
- 프론트엔드 문항의 `sourceRefs`에는 옛 경로(`source/Web_복습노트.md`)가 남아 있다. 고치면 contentVersion이 바뀌어 저장된 응시 기록에 안내가 뜨므로 이번에는 두고 README에만 새 경로를 적는다.

## 4. 출제 범위와 블루프린트

### 4-1. 범위 파일

`source/AI역량검사/scope-ai.json`을 만든다. 프론트엔드 범위 파일과 같은 구조로 대주제(버튼 단위)와 세부 태그를 두고, 태그마다 강의 파일과 슬라이드 구간을 적는다. md에 글자가 없으므로 이 파일이 문항 작성과 검수의 기준 목차가 된다.

| 대주제 ID | 버튼 이름 | 강의 |
| --- | --- | --- |
| `ml` | AI와 기계학습 | 1-1, 1-2 |
| `nlp` | 자연어 처리 | 2-1, 3-1 2차시의 RNN과 어텐션 |
| `vision` | 딥러닝과 영상 모델 | 3-1 1차시, 3-1 2~3차시의 ViT와 학습 전략 |
| `llm-agent` | LLM과 에이전트 | 4-1 |
| `efficiency` | 리소스 최적화 | 5-1 |

- RNN, LSTM, 어텐션은 2-1과 3-1에 모두 나온다. 한 회차 안의 중복을 막으려고 `nlp`에만 둔다. 지식 증류는 3-1(DeiT)과 5-1에 모두 나오며 `efficiency`에 둔다.
- 세부 태그는 약 45개로 잡고 3회를 합쳐 모든 태그가 한 번 이상 나오게 한다. 태그 목록은 개념 요약 노트의 절 제목과 맞춘다.

### 4-2. 필기 검정형 (회차마다 객관식 100문항, 120분)

| 대주제 | 강의 | 문항 |
| --- | --- | ---: |
| AI와 기계학습 | 1-1 | 11 |
| | 1-2 | 13 |
| 자연어 처리 | 2-1 | 16 |

| LLM과 에이전트 | 4-1 | 20 |
| 리소스 최적화 | 5-1 | 16 |

- 9절에서 PDF 전용 강의를 넣기로 하면 위 비율을 줄여 3-2, 4-2, 5-2에 5문항씩 15문항을 준다.
| 문항 성격 | 문항 |
| --- | ---: |
| 개념 이해 | 35 |

- 회차 방향: 1회 개념과 기본 계산, 2회 상황 판단과 오류 찾기, 3회 여러 강의를 잇는 응용. 숫자만 바꾼 중복 문항은 만들지 않는다.
- 정답 분포: 회차 100문항은 QUESTION_AUTHORING.md 2절의 일반 N 규칙에 따라 번호별 24~26개, 3회 300문항은 74~76개다. 대주제별 연습 세트도 같은 규칙으로 검사한다.

### 4-3. 실기 검정형 (회차마다 8문항, 100점, 120분)

예시의 형식을 따르되 데이터와 과제는 바꾼다. 데이터는 scikit-learn에 들어 있는 자료나 지원 모듈에 넣은 합성 자료만 쓴다(인터넷 없음).

| 문항 | 1회 표 데이터(유방암 이진 분류) | 2회 텍스트(합성 문의 문장) | 3회 이미지와 경량화(digits 8×8) |
| ---: | --- | --- | --- |
| 1 | 층화 분할과 학습 자료 기준 표준화 (12) | 토큰화와 어휘 사전, 원-핫 (12) | 텐서 모양 바꾸기와 정규화 (10) |
| 2 | 상관관계와 분포 확인 (10) | TF-IDF와 코사인 유사도 상위 k 검색 (14) | 합성곱 출력 크기와 파라미터 수 (12) |
| 3 | 로지스틱 회귀와 확률 예측 (12) | 청킹과 검색 결과로 프롬프트 만들기 (12) | CNN 구성 (14) |
| 4 | 정밀도와 재현율, ROC-AUC (14) | 임베딩과 평균 풀링 분류기의 출력 모양 (12) | DataLoader 학습 루프와 정확도 (16) |
| 5 | MLP 구성과 BCEWithLogitsLoss (14) | LSTM 입출력 모양과 마지막 은닉 상태 (12) | 백본 고정과 학습 파라미터 수 (12) |
| 6 | 학습 루프와 조기 종료 기록 (16) | 학습 루프와 손실 기록 (16) | 학습률 스케줄러 적용과 기록 (10) |
| 7 | 가중치 감쇠와 평가 모드 예측 (10) | 혼동행렬과 클래스별 재현율 (12) | 대칭 INT8 양자화와 복원 오차 (14) |
| 8 | 임계값 결정과 근거 서술 (12) | 희소 검색과 밀집 검색의 선택 서술 (10) | LoRA 저랭크 갱신과 파라미터 수, 서술 (12) |

- 문항끼리 답안을 주고받지 않는다. 같은 문항 안에서만 앞 소문항의 결과를 쓴다. 시드는 고정한다.
- 서술 소문항은 결과 해석과 기술 선택 근거를 묻고 채점 기준을 따로 둔다.
- LLM API 호출이나 사전학습 가중치 내려받기가 필요한 과제는 내지 않는다. RAG는 검색과 프롬프트 문자열 조립까지만 하고, 전이 학습은 지원 파일로 넣은 작은 사전학습 가중치를 쓴다.
- 시험 환경에 LangChain이 설치되는지 알 수 없다. LangChain 코드는 필기의 코드 읽기 문항으로만 다룬다(9절 결정 4).

## 10. 모의평가_생성계획.md와의 관계

이 파일은 SK하이닉스 AI 해커톤 예선 대비 계획이지만 9절 개념 정리의 U1~U10은 같은 SSAFY AI 강의 10권을 정리했다. 그래서 아래를 가져오고 다른 점은 따로 둔다.

**가져오는 것**

- 개념 정리 형식(정의, 실무 상황, 흔한 오해, 올바른 조치). 개념 요약 노트의 "자주 틀리는 포인트"를 오답 선지 재료로 쓴다.
- 개념 ID(K101~K1006). `scope-ai.json`의 세부 태그에 대응하는 K ID를 함께 적어 두 계획에서 같은 개념을 같은 이름으로 부른다.
- 오답 선지 패턴 네 가지와 교재 확인문제의 함정 목록. 패턴은 원리 왜곡과 조건 일부 누락, 극단적 조치와 층위 착오이고 함정은 포함관계 뒤집기와 절대어, 역할 뒤바꾸기와 재학습 여부 혼동이다. 단 절대어가 오답에만 몰리지 않게 QUESTION_AUTHORING.md 1절로 다시 검사한다.
- 블라인드 재풀이와 생성 스크립트로 정답 계산(시드 고정), 함정이 실제로 작동하는지 확인하는 검사. 실기 검증의 "빈 템플릿으로 검사가 실패해야 한다"가 이것에 해당한다.
- 응시 후 오답을 개념별로 모아 다음 회차에서 비중을 올리는 순환. 사이트의 `틀린 문제만` 복습과 주제 버튼으로 먼저 대응하고, 회차 블루프린트를 정할 때 반영한다.

**다른 점**

- SK 시험은 업무 시나리오형 지식평가와 AI 활용평가다. 이 트랙은 강의 내용의 객관식 100문항과 Jupyter 코딩이다.

- 계획과 다른 점
  - 실기 1회는 표에서 정한 이진 분류 한 가지로 만들었고 문항 구성은 계획의 1회 열과 조금 다르다. 층화 분할, 분포 확인, 로지스틱 회귀, 지표 계산, 신경망 구성, 학습 루프와 조기 종료, 드롭아웃과 평가 모드, 임계값 선택이다.
  - 필기 실행 코드는 `scripts/ai_checks.py` 대신 `source/AI역량검사/ai-written-checks.json`에 두었다.
  - 실기 노트북 내려받기는 만들지 않았다.
  - 필기 문항의 난이도는 쉬움 25, 보통 50, 어려움 25이다.
- 확인이 필요한 사항
  - 필기 81문항의 재풀이는 작성자가 한 기록이다. 다른 사람이 한 번 검토한 뒤 배포한다.
  - 슬라이드는 이미지라서 문항 근거를 슬라이드 단위가 아니라 강의 파일과 절 이름으로 적었다.
  - 실기 문항은 로컬에서 Python 3.12와 `requirements-ai.txt`의 버전으로 실행했다. 시험 환경(Python 3.11 이상)에서의 실행은 확인하지 못했다.
