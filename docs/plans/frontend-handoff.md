# 프론트엔드 문제은행 인수인계

작성일: 2026-10-10. 구현 계획과 결과는 [frontend.md](frontend.md)에 있다. 이 문서는 이어서 작업할 때 확인할 일만 모았다.

## 현재 상태

- 브랜치 `feat/mock-exam`에 프론트엔드 3회(96문항)와 트랙 구조, 화면, 검증 도구가 들어 있다.
- 검증 명령은 모두 통과했다. 콘텐츠 검증 오류 0건, 편향 검사 미검토 0건, 프론트엔드 답안 96/96, 단위 테스트 15개, e2e 16개.
- 배포(GitHub Pages)와 원격 PR은 아직 확인하지 않았다.

## 확인이 필요한 사항

1. **재풀이 문항 검토**: 코드를 실행하지 못한 23문항은 작성자가 정답을 가리고 다시 풀어 확인했다. 목록은 `source/frontend-reviews.json`이다. 다른 사람이 한 번 검토한 뒤 배포한다.
2. **수정한 기존 문항**: `subject-01-q18`과 `subject-01-q20`의 선지 순서를 바꾸고 revision을 올렸다. 이진 탐색 주제 세트의 같은 번호 3연속을 없애기 위해서다. 내용은 그대로인지 한 번 본다.
3. **커밋하지 않은 파일**:
   - `A형대비/`는 Java 소스와 class 파일이다. 저장소에 넣을지 정한다.
   - `source/sw advanced.txt`는 범위 참고 자료다. 공개 저장소에 넣어도 되는지 정한다.
   - `requirements-dev.txt` 삭제는 이번 작업 전부터 있던 변경이다. 의도한 삭제인지 확인한다.
4. **PR 본문**: 범위와 문항 수, 정답 분포, 최대 연속 길이, 길이 편향 검토, 정답 검수 결과를 적는다. 수치는 아래 표를 쓴다.
5. **GitHub Pages 확인**: 이 저장소는 main push로 배포 실행이 생기지 않는 상태였다(README 참고). `npm run deploy` 후 공개 주소에서 프론트엔드 탭, 주제 버튼, 모바일 코드 표시를 확인한다.
6. **실기기 확인**: 코드 상자는 Playwright의 360px 화면에서만 검사했다. 실제 휴대폰에서 줄바꿈과 글자 크기를 본다.

## 이어서 할 만한 작업

- 문항을 고치면 해당 문항의 revision을 올리고 `scripts/frontend_checks*.mjs`의 revision과 `choice` 문구도 같이 맞춘다. 맞지 않으면 검증이 실패한다.
- 4회 이상을 추가할 때는 `source/frontend-04/`를 만들고 `tests/e2e/frontend.spec.js`의 회차 목록과 `features.test.js`의 `assert.equal(files.length, 3)`를 고친다.
- 주제별 연습 세트는 회차 순서대로 정답 순서를 검사한다. 회차를 추가하면 세트가 길어지므로 `audit_bias.py` 결과를 다시 본다.
