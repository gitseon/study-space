# ADsP 문제은행 구현 계획

작성일: 2026-10-22. 상태: 1회 구현 완료, 2회와 3회 미작성.

## 1. 확정된 결정

- 회차: ADsP 3회를 목표로 하고 1회를 먼저 만든다. 회차마다 객관식 50문항이다. 1과목 데이터 이해 10, 2과목 데이터 분석 기획 10, 3과목 데이터 분석 30으로 나눈다.
- 단답형과 서술형은 두지 않는다. 개념 요약 노트 버튼도 만들지 않는다.
- 회차 종류는 기존 `subject`를 재사용한다. 화면에서는 과목평가 카드로 보인다.
- 트랙 이름은 ADsP이고 폴더는 `source/adsp/`다.
- 출제 범위 원본은 개인 소장 요약 노트다. 저작권 보호 자료라서 저장소에 넣지 않고 `private/`에 둔다. 공개 저장소에는 직접 쓴 범위 파일과 문항만 둔다.

## 3. 파이프라인 변경

기존 검증 스크립트는 회차 구성과 대주제별 문항 수를 트랙의 scope 파일에서 읽는다. 그래서 스크립트 수정 없이 설정만으로 동작한다.

- `scripts/build_data.py`의 `TRACKS`에 `adsp`를 등록한다.
- `source/adsp/scope-adsp.json`에 `composition`(`subject`: 객관식 50)과 `groups`와 `tags`를 둔다.
- 새 파일: `scripts/verify_adsp_answers.py`, `source/adsp/adsp-checks.json`, `source/adsp/adsp-reviews.json`, `tests/e2e/adsp.spec.js`.
- `check.yml`과 PR 템플릿과 README에 새 검증 명령을 더한다.
- 기존 `tests/content`와 `tests/e2e/frontend.spec.js`의 트랙 개수 기대값을 3에서 4로 고친다.

## 4. 출제 원칙

- 개념과 사실만 쓰고 요약 노트의 문장, 표, 예제 수치, 비유를 옮기지 않는다. 상황과 숫자는 새로 만든다.
- 교재마다 다르게 쓰는 값(데이터 분할 비율, t분포를 쓰는 표본 수 기준 등)은 정답 근거로 쓰지 않는다. 노트에 부정확한 설명이 있으면 올바른 정의로 쓴다.
- 계산 문항은 코드로 실제 계산해 정답 선지에 그 값이 들어 있는지 확인한다. 1회에서는 14문항이 해당한다. 나머지 36문항은 재풀이 기록으로 확인한다.
- 오답은 헷갈리기 쉬운 개념으로 만들고 각 오답에 근거를 해설에 적는다.
- 정답 번호는 회차에서 번호별 11~14개, 3회 합계 150문항에서 36~39개다.

## 6. 위험과 주의

- 2회와 3회를 더하면 정답 번호 합계 기준(번호별 36~39개)을 새로 만족시켜야 한다. 회차마다 위치를 정할 때 앞 회차의 분포를 함께 본다.
- 요약 노트의 일부 서술은 정확하지 않거나 교재마다 다르다. 그 부분은 출제하지 않거나 올바른 정의로 바꿔 쓴다.
- 실제 시험의 출제 형식과 배점은 노트에 없다. 이 문제은행은 연습용이며 실제 출제를 보장하지 않는다.
