# 학습 원본 출처의 공개 방안

작성일: 2026-11-03. 대상은 공개 계획 문서, 직접 작성한 노트, 이후 제작할 문항의 출처 표기다. 원본 파일은 로컬에 보존한다.

## 1. 대안과 권장안

원본 파일명이 적혀 있다는 사실만으로 원본 내용이 공개된 것은 아니다. 다만 자료의 이름·교육 차수·날짜를 노출하고, 나중에 링크나 원본을 함께 커밋하기 쉬워진다. 파일명 삭제와 원본 공개 제외는 서로 다른 조치다.

| 방식 | 장점 | 제약 | 판단 |
| --- | --- | --- | --- |
| 공개 문서에 원본명 유지 | 작성자가 즉시 원본을 찾음 | 외부 공개 가능한 명칭인지 매번 검토, 원본 경로 노출 | 공개 자료에 한정 |
| 계획 문서 전체를 Git 제외 | 자료명도 밖에 나가지 않음 | 설계·검토 이력과 협업 기준이 사라짐 | 개인 메모에 한정 |
| 공개 자료 ID + 비공개 원본 대응표 | 계획 공유와 출처 추적을 함께 유지 | 로컬 대응표의 별도 보관 필요 | 권장 |

공개 문서에는 `DB-L01`, `SQLD-A`, `BE-ASSESS-01`처럼 자료 ID와 개념·절을 적는다. 정확한 원본명과 절대 경로 및 해시는 Git에서 제외한 `private/backend-db/source-index.json`에 둔다. 이 대응표를 잃으면 원본 추적이 어려우므로 개인 비공개 백업 대상에 포함한다.

## 2. 자료 ID 규칙

| 자료 ID | 공개 설명 |
| --- | --- |
| `DB-L01~09` | DB 기초와 SQL, 모델링과 JDBC 교재 |
| `DB-D01~07` | 일차별 DB 보충 강의 |
| `SQLD-A`, `SQLD-B` | SQLD 개정형 개념 자료, 구판 핵심 개념 자료 |
| `SQLD-A-F01~02`, `SQLD-B-F01~14` | 해당 자료의 참고 그림 |
| `BE-ASSESS-01`, `BE-SCOPE-01`, `BE-CLASS-01` | 평가 안내, 과목·월말 범위, 보충 수업 정리 |
| `BE-LAB-01~10` | 차수별 실습·과제 묶음 |
| `BE-LAB-WS-01-1` 등 | WS/HW·차수·단계별 개별 요구사항. 묶음 ID는 개별 항목의 그룹 |
| `AI-ASSESS-01~02`, `AI-CLASS-01` | AI 평가 안내·FAQ·설명회 자료 |

공식 공개 문서는 별칭으로 감추지 않고 공식 페이지의 제목과 URL로 출처를 남긴다. 직접 작성한 공개 원고·코드의 파일명도 그대로 링크할 수 있다. 이 정책은 모든 파일명이나 이미지 확장자를 금지하는 규칙이 아니다.

현재 대응표에는 파일의 ID와 경로 및 SHA-256을 저장했다. 최초 검토한 요구사항 이미지와 참고 자료가 대상이며 모든 실습 프로젝트 파일을 해시로 기록한 것은 아니다. 문항 제작 시 참고한 Java와 JSP 및 SQL의 경로와 절도 별도 ID로 등록한다. 출제 근거는 원본의 개념과 절까지 찾아갈 수 있어야 한다.

## 3. 이번에 적용한 정리

- 백엔드·DB 계획의 원본명 표를 자료 ID 표로 바꾸고, AI 계획의 평가 안내·전사 이름도 ID로 바꿨다.
- 이번에 작성한 DB 노트의 근거에 있는 원본명과 일차 표기를 같은 ID로 바꿨다. 개념 설명·예제의 내용은 변경하지 않았다.
- DB 원본 PDF에 더해 참고 Markdown과 추출 이미지 폴더, 백엔드 평가 안내·범위 자료가 우발적으로 추적되지 않도록 `.gitignore`에 규칙을 추가했다. 새로 작성하는 SQLD 공개 노트는 `source/sqld/`에 두므로 원본 제외 규칙과 충돌하지 않는다.
- 원본 파일과 외부 실습 폴더는 이동·삭제·수정하지 않았다. 기존 커밋 이력도 다시 쓰지 않았다.

`.gitignore`는 이미 추적 중인 파일을 숨기지 않는다. 새 원본이 비추적·제외 상태인지 `git ls-files`와 `git check-ignore`로 함께 확인한다. 이미 공개된 원본이 발견되면 별도 제거 변경과 사용자 검토를 거치며 이 작업에서 임의로 이력을 삭제하지 않는다.

## 4. 문항 제작 전 지침 정합성

현재 저장소 지침은 `sourceRefs`에 강의 파일과 절을 쓰도록 요구한다. 단순히 출처를 지우면 이 요구를 충족하지 못한다. 신규 backend·SQLD 문항 작성 단계에서 AGENTS.md와 `docs/QUESTION_AUTHORING.md`에 다음 정책을 함께 반영한다.

> 비공개 원본은 공개 sourceRefs에 등록된 자료 ID와 절·쪽을 기록한다. 정확한 파일명과 경로 및 해시는 비공개 대응표에 보관한다. 공식 공개 출처는 문서 제목과 URL을 기록한다. 출처 대응을 검증하지 못한 문항은 공개하지 않는다.

아직 신규 문항의 `sourceRefs`를 만들거나 기존 모든 트랙의 출처를 바꾸지 않았다. 지침의 예외를 조용히 적용하지 않고 구현 작업에 명시한다. 개인 대응표가 없는 공개 CI에서도 문항을 검증할 수 있도록 공개 ID 목록은 `source/provenance.json`으로 만들되 경로·파일명·해시 없이 `{id, description, allowedSections}`만 제공하는 안이다.

## 5. 구현할 공개 검사

신규 `scripts/check_public_sources.py`를 추가한다. `--public-only`는 공개 ID 목록과 sourceRefs, 공개 산출물의 절대 로컬 경로·private 경로를 검사한다. `--private-index <path>`는 로컬 대응표의 파일 해시와 원본명·원본 경로의 공개 문서 누출까지 추가 검사한다. 성공은 종료 코드 0, 위반은 1이며 보고서에는 공개 가능한 ID와 위반 파일 위치만 쓴다. 비공개 경로가 CI 로그에 재노출되지 않게 한다.

- [ ] `tests/content/test_public_sources.py`: 허용된 공개 코드 경로와 공식 URL은 통과한다. 등록되지 않은 자료 ID는 실패한다. 원본명과 절대 로컬 경로 및 원본 이미지 링크도 실패한다.
- [ ] 빌드 입력과 배포 복사는 기존 허용 목록을 유지한다. `source/` 전체나 `private/`, `reports/`, 외부 실습 폴더를 통째로 배포하는 복사를 추가하지 않는다.
- [ ] 로컬에서 정확한 원본명으로 `docs/plans/`, 공개 노트·문항, `data/`, `dist/`를 검사한다. 일반적인 이미지/PDF 확장자만으로 작성자가 만든 공개 그림까지 차단하지 않는다.
- [ ] `git ls-files`로 원본 추적 여부, `git check-ignore`로 제외 여부를 확인한다. 커밋을 요청받은 시점에 `git diff --cached --name-only`와 staged diff를 다시 검사한다.
- [ ] 기존 이력에 원본명만 있는 경우 이력 재작성 없이 앞으로의 문서에서 정리한다. 실제 원본이나 민감정보가 추적된 경우에는 해당 파일을 특정해 별도 처리한다.

이번 작업에서는 위 검사의 로컬 확인을 수행하며 정식 검사 스크립트와 CI 도입은 후속 구현 범위다. 파일명 비식별화가 자료의 사용이나 재배포 권한을 새로 주는 것은 아니므로 원본 문구와 이미지 및 과제 정답을 옮기지 않는 원칙도 유지한다.
