# STS 검증 절차: 도서 관리

이 문서는 모범답안(`reference/`)이 실제 환경에서 동작하는지 Spring Tools for Eclipse(STS)에서 확인하는 절차입니다. 구현 코드는 `reference/` 폴더에 따로 있고, 단계별 연습 시작 파일은 `starter/`와 `stages/`에 있습니다. 이 문서는 학습자에게 공개하는 자료가 아닙니다.

검증 대상 환경은 OpenJDK25U-jdk hotspot 25.0.3_9, Apache tomcat-11.0.27, Dynamic web module version 6.0, mysql 8.4.11입니다. 이 문서를 만든 시점에는 `javac` 컴파일(Java 21 릴리스, Servlet API 6.0.0)만 확인했고 JSP 번역, Tomcat 기동, DB 연결은 확인하지 않았습니다. 아래 결과표를 채워 알려 주세요.

## 1. 준비

1. MySQL에서 `reference/src/main/resources/ssafy_book.sql`을 실행합니다. 데이터베이스 `ssafy_book`가 만들어지고 같은 이름의 기존 데이터베이스는 초기화됩니다. 다른 이름의 데이터베이스는 건드리지 않습니다.
2. MySQL 계정은 `src/main/java/com/ssafy/sample/util/DBUtil.java`의 `ssafy` / `ssafy`입니다. 다르면 이 파일의 USER와 PASSWORD를 로컬에 맞게 바꿉니다.
3. STS에서 `File > Import > Maven > Existing Maven Projects`로 `reference/` 폴더를 선택합니다.
4. 프로젝트의 Java Compiler 준수 수준이 21 이상인지, `Project Facets`의 Dynamic Web Module이 6.0인지 확인합니다. Maven 가져오기에서 facet이 6.0으로 잡히지 않으면 `Properties > Project Facets`에서 6.0으로 맞추고 Runtimes에서 Tomcat 11.0.27을 선택합니다.
5. `Servers` 탭에서 Tomcat v11.0 서버를 만들고 이 프로젝트를 추가한 뒤 시작합니다. 접속 주소는 `http://localhost:8080/<컨텍스트 이름>/`입니다. 컨텍스트가 `/`가 아닌 경우의 기대 동작도 같습니다.

가져오기에서 `mysql-connector-j`, JSTL 의존성 오류가 나면 `Maven > Update Project`로 다시 받습니다.

## 2. 점검 항목

각 항목을 순서대로 실행하고 결과표에 `통과`, `실패`, `해당 없음` 중 하나와 메모를 적습니다. 항목 번호는 사이트의 체크리스트 ID와 같습니다.

### run-build. 로컬 프로젝트 빌드와 기동

1. 내려받은 ZIP을 새 폴더에 풀고 Spring Tools for Eclipse에서 Maven 프로젝트로 가져옵니다.
2. src/main/resources의 SQL 파일을 MySQL에서 실행해 시작 데이터를 만듭니다.
3. Tomcat 11.0.27에 프로젝트를 추가하고 서버를 시작한 뒤 메인 페이지를 엽니다.

기대 결과: 컴파일 오류 없이 서버가 시작되고 메인 페이지가 열립니다.

### crd-list. 도서 목록 조회

1. 로그인한 뒤 목록 조회를 엽니다.
2. 표의 행 수와 각 값을 시작 데이터와 비교합니다.
3. DB의 도서 행을 모두 지우고 목록을 다시 엽니다.

기대 결과: 시작 데이터 4행이 코드 순서로 보입니다. 데이터가 없으면 안내 행이 보입니다.

### crd-create. 도서 등록

1. 등록 화면에서 겹치지 않는 코드와 한글 이름, 가격을 입력해 등록합니다.
2. 목록과 상세 화면에서 입력한 값을 확인합니다.
3. DB에서 해당 행을 조회합니다.

기대 결과: DB에 1행이 추가되고 목록과 상세의 값이 입력과 같으며 한글이 깨지지 않습니다.

### crd-prg. 등록 후 새로고침

1. 등록을 완료해 목록이 보이는 상태에서 새로고침합니다.
2. 브라우저가 폼 재전송을 묻는지 확인하고 목록 행 수를 셉니다.

기대 결과: 같은 항목이 다시 등록되지 않고 주소가 목록 주소입니다.

### crd-detail. 상세 조회

1. 목록에서 코드를 눌러 상세 화면을 엽니다.
2. 주소창에 없는 코드를 넣어 상세 주소를 직접 엽니다.

기대 결과: 있는 항목은 값이 모두 보이고 없는 항목은 404 오류 화면입니다.

### crd-delete. 삭제

1. 상세 화면의 삭제 버튼으로 항목을 삭제합니다.
2. 목록과 같은 코드의 상세 주소를 다시 엽니다.
3. 주소창에 삭제 주소(action=delete&code=...)를 직접 입력해 GET으로 요청합니다.

기대 결과: DB에서 항목이 사라지고 상세는 404입니다. GET 삭제 요청은 405이며 데이터가 바뀌지 않습니다.

### crd-invalid. 잘못된 입력과 중복 코드

1. 가격을 비우거나 음수나 문자로 바꾸어 등록합니다.
2. 이미 있는 코드로 등록합니다.
3. 비숫자 가격은 개발자 도구나 직접 요청으로 보내 재현합니다.

기대 결과: 500 오류 없이 안내 문구와 등록 화면이 보이고 잘못된 행이 DB에 추가되지 않습니다.

### auth-login. 로그인

1. 올바른 이메일과 비밀번호로 로그인합니다.
2. 틀린 비밀번호로 로그인합니다.

기대 결과: 성공하면 목록으로 이동하고 머리글에 사용자 이름이 보입니다. 실패하면 로그인 화면에 안내가 보입니다.

### auth-cookie. 이메일 기억하기

1. 이메일 기억하기를 선택해 로그인한 뒤 로그아웃하고 로그인 화면을 엽니다.
2. 기억하기를 해제해 다시 로그인한 뒤 로그아웃하고 로그인 화면을 엽니다.

기대 결과: 선택했을 때는 이메일이 채워지고 체크되어 있으며 해제하면 비어 있습니다. 브라우저 쿠키 목록에서 email 쿠키가 같은 path로 저장되고 삭제됩니다.

### auth-logout. 로그아웃

1. 로그아웃을 누릅니다.
2. 목록 주소를 직접 열어 봅니다.

기대 결과: 메인으로 이동하고 머리글에 로그인 링크가 보입니다. 목록 주소는 로그인 화면으로 이동합니다.

### auth-filter. 로그인 필요 요청 차단

1. 로그인하지 않은 상태에서 목록, 등록, 상세 주소를 직접 엽니다.
2. 같은 상태에서 로그인 화면과 메인 화면을 엽니다.
3. JSP 파일 주소(/book/list.jsp)를 직접 열어 봅니다.

기대 결과: /book 요청은 로그인 화면으로 이동합니다. 로그인 화면과 메인은 열립니다. JSP 직접 접근은 막히지 않으며 이는 연습 범위 밖 한계로 기록합니다.

### jsp-render. JSP 출력 안전성

1. 이름에 <b>굵게</b> 같은 HTML 문자가 들어간 항목을 DB에 직접 넣거나 등록합니다.
2. 목록, 상세, 머리글을 확인합니다.

기대 결과: 입력한 문자가 그대로 글자로 보이고 태그나 스크립트로 실행되지 않습니다.

### error-pages. 오류 화면

1. 존재하지 않는 주소를 엽니다.
2. 알 수 없는 action 값(예: /book?action=zzz)을 요청합니다.
3. MySQL 서비스를 잠시 멈추고 목록을 엽니다. 확인 뒤 서비스를 다시 시작합니다.

기대 결과: 404와 500 오류 화면이 보이고 예외 이름이나 SQL 같은 내부 정보는 보이지 않습니다.

### project-export. 내려받은 프로젝트 구성

1. 내려받은 ZIP을 새 폴더에 풉니다.
2. pom.xml, src, SQL 파일이 있는지와 target, build, 정답 코드가 없는지 확인합니다.

기대 결과: 실행에 필요한 파일만 있고 모범답안과 컴파일 산출물이 없습니다.
