# 스터디실 예약 관리 실행 검증 기록

이 문서는 모범답안(`reference/`)을 사람이 직접 확인하는 절차입니다. 자동 검증(컴파일, 단위, DB 통합, HTTP, JSP 렌더링)은 `scripts/verify_spring_projects.py`가 실행해 `review.json`에 기록합니다. STS에서의 수동 실행은 사용자가 직접 확인하기 전까지 미검증으로 둡니다.

## 확인 절차

### run-build. 로컬 프로젝트 빌드와 기동

1. 내려받은 ZIP을 새 폴더에 풀고 STS에서 Maven 프로젝트로 가져옵니다.
2. 환경 변수 DB_URL, DB_USER, DB_PASSWORD를 설정하고 스터디용 스키마를 만듭니다.
3. StudyRoomApplication을 실행하고 http://localhost:8080/ 을 엽니다.

기대 결과: 컴파일 오류 없이 시작되고 예약 목록 화면이 열립니다.

### crd-list. 예약 목록 조회

1. 목록 화면을 엽니다.
2. 표의 행 수와 각 값을 시작 데이터와 비교합니다.
3. 예약을 모두 취소하고 목록을 다시 엽니다.

기대 결과: 시작 데이터 3행이 번호 순서로 보입니다. 예약이 없으면 안내 행이 보입니다.

### crd-search. 방과 이름으로 검색

1. 방 선택만 바꿔 검색합니다.
2. 예약자 이름 일부만 입력해 검색합니다.
3. 방과 이름을 함께 입력해 검색하고 아무것도 입력하지 않고도 검색합니다.

기대 결과: 조건에 맞는 행만 보이고 조건이 없으면 전체가 보입니다.

### crd-detail. 예약 상세

1. 목록의 번호 링크를 누릅니다.
2. 번호, 방, 예약자, 인원을 목록과 비교합니다.

기대 결과: 목록과 같은 값이 상세 화면에 보입니다.

### crd-notfound. 없는 예약과 잘못된 번호

1. 주소의 번호를 존재하지 않는 값으로 바꿔 엽니다.
2. 번호 자리에 숫자가 아닌 글자를 넣어 엽니다.

기대 결과: 없는 번호는 404 오류 화면이고 숫자가 아닌 번호는 400입니다. 빈 상세 화면은 나오지 않습니다.

### crd-create. 예약 등록과 새로 고침

1. 예약하기 화면에서 방, 예약자, 인원을 입력해 예약합니다.
2. 이동한 상세 화면을 새로 고침합니다.
3. 목록으로 돌아가 행 수를 확인합니다.

기대 결과: 상세 화면으로 이동해 안내가 보이고 새로 고침해도 예약이 늘지 않습니다.

### crd-invalid. 입력 검증 실패

1. 예약자 이름을 비워 두고 예약합니다.
2. 인원에 0을 넣고 예약합니다.

기대 결과: 저장되지 않고 오류 메시지와 함께 입력 화면이 다시 보이며 입력한 값이 유지됩니다.

### crd-full. 남은 자리 초과

1. 정원이 4명인 방에 이미 2명이 예약되어 있을 때 3명을 예약합니다.
2. 목록에서 그 방의 예약이 늘지 않았는지 확인합니다.

기대 결과: 409 화면이 나오고 예약은 저장되지 않습니다.

### crd-cancel. 예약 취소

1. 상세 화면에서 예약 취소를 누릅니다.
2. 목록에서 그 예약이 사라졌는지 확인합니다.
3. 이미 취소한 예약의 상세 주소를 다시 엽니다.

기대 결과: 목록으로 돌아가 안내가 보이고 예약이 사라집니다. 이미 취소한 예약은 404입니다.
