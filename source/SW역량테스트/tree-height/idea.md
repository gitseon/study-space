## 문제 요약

나무가 N그루 있고 높이가 제각각입니다. 홀수 번째 날에는 한 그루를 1만큼, 짝수 번째 날에는 한 그루를 2만큼 키울 수 있고 하루에 한 그루까지만 키우거나 쉴 수 있습니다. 모든 나무의 높이를 같게 만드는 최소 날짜를 구합니다.

입력은 테스트 수 T, 각 테스트의 N, 나무 높이 N개이고 출력은 `#번호 날짜 수`입니다.

## 발상

1. 목표 높이를 가장 큰 나무의 높이로 잡습니다. 더 높게 맞추면 키울 양만 늘어납니다.
2. 나무마다 부족한 높이 diff를 `+2` 작업 `diff / 2`번과 `+1` 작업 `diff % 2`번으로 나눕니다. 모든 나무의 `+1` 작업 수를 one, `+2` 작업 수를 two로 모읍니다.
3. `+1` 작업은 홀수 날에만, `+2` 작업은 짝수 날에만 할 수 있습니다. one번째 홀수 날은 `2 * one - 1`일째이고 two번째 짝수 날은 `2 * two`일째입니다. 둘 중 늦은 날이 끝나는 날입니다.
4. two가 one보다 많이 크면 홀수 날이 남아서 낭비됩니다. `+2` 작업 하나를 `+1` 작업 두 개로 바꾸면 two는 1 줄고 one은 2 늘어 둘의 차이가 3 줄어듭니다. `two - one`이 2 이상인 동안 이 바꾸기를 반복해 두 횟수의 균형을 맞춥니다.
5. 균형을 맞춘 뒤 답은 `max(2 * one - 1, 2 * two)`입니다.

## 놓치기 쉬운 점

- 부족한 높이의 합만 보고 날짜를 계산하면 홀수 날과 짝수 날의 제한을 반영하지 못합니다.
- 모든 나무가 이미 같으면 one과 two가 0이라 `2 * one - 1`은 -1이 되지만 `max`가 0을 고릅니다.
- 테스트마다 one과 two를 새로 시작해야 합니다.
- 바꾸기 반복은 `(two - one) / 3`만큼 한 번에 옮기고 남은 차이가 2일 때 한 번 더 바꾸는 식으로 줄여도 같은 결과입니다.

## 복잡도와 검증

높이를 읽고 나누는 데 O(N)입니다. 균형을 맞추는 바꾸기는 위의 식으로 한 번에 옮기면 상수 시간이라 전체가 O(N)입니다.

작은 입력 60개를 날짜별로 모든 선택을 따져 보는 완전탐색과 비교해 확인했습니다. 이 탐색은 목표 높이를 최대 높이보다 높게 잡는 경우도 포함합니다.
