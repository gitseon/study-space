# SQLD 개념 요약 노트

SQLD(SQL 개발자) 필기 준비를 위한 개념 정리다. 시험은 객관식 50문항이며 1과목 데이터 모델링의 이해 10문항과 2과목 SQL 기본 및 활용 40문항으로 이루어진다. 이 노트는 공개된 출제 범위를 기준으로 직접 정리한 학습 자료이며 실제 출제를 보장하지 않는다.

SQL 문제는 DBMS마다 결과가 다른 경우가 많다. 이 노트는 Oracle과 SQL Server를 기준으로 하고 두 DBMS가 같은 규칙은 공통, 다른 규칙은 각각 표시한다. 수업에서 쓰는 MySQL의 규칙을 그대로 가져오지 않는다. 확인하지 못한 버전별 차이는 단정하지 않는다.

## Part 1. 데이터 모델링의 이해

### 1. 모델링의 세 단계

| 단계 | 하는 일 | 예 |
|---|---|---|
| 개념 모델링 | 업무에 필요한 엔터티와 관계를 큰 틀로 정한다 | 고객과 주문이 있다 |
| 논리 모델링 | 속성과 식별자와 정규화를 정한다. DBMS와 무관하다 | 주문번호가 주문의 식별자이다 |
| 물리 모델링 | 테이블과 열 이름과 자료형과 인덱스를 정한다. DBMS를 고려한다 | `NUMBER(10)` 형 열 |

- ANSI 3단계 스키마는 사용자가 보는 외부 스키마와 전체 구조를 나타내는 개념 스키마와 저장 방식을 나타내는 내부 스키마로 나뉜다.
- 논리적 독립성은 개념 구조가 바뀌어도 외부 화면이 영향을 받지 않는 성질이고 물리적 독립성은 저장 방식이 바뀌어도 개념 구조가 영향을 받지 않는 성질이다.

### 2. 엔터티

엔터티는 업무에서 관리해야 하는 대상이다. 엔터티가 되려면 다음을 갖춰야 한다.

- 업무에서 필요하고 관리하는 정보여야 한다.
- 유일한 식별자로 인스턴스를 구분할 수 있어야 한다.
- 인스턴스가 두 개 이상 있어야 한다. 한 건뿐인 정보는 엔터티보다 속성에 가깝다.
- 속성을 가져야 하고 다른 엔터티와 관계를 맺어야 한다.

| 분류 기준 | 종류 |
|---|---|
| 유무형 | 유형(고객 상품) 개념(부서 계약) 사건(주문 결제) |
| 발생 시점 | 기본(독립적으로 생기는 것) 중심(기본에서 생겨 업무를 이끄는 것) 행위(중심 사이에서 생기는 이력) |

### 3. 속성

- 엔터티가 가진 더 쪼갤 수 없는 정보의 단위이다. 인스턴스 하나에서 한 속성은 하나의 값만 갖는다.
- 특성에 따라 기본 속성(원래 있는 값) 설계 속성(업무 규칙으로 만든 값) 파생 속성(계산해서 얻는 값)으로 나눈다.
- 구성 방식에 따라 PK 속성 FK 속성 일반 속성으로 나눈다.
- 분해 가능 여부에 따라 단일 속성 복합 속성(주소의 시와 구) 다중값 속성(한 사람의 여러 전화번호)으로 나눈다. 다중값 속성은 별도 엔터티로 분리한다.

### 4. 관계

| 요소 | 뜻 | 확인할 점 |
|---|---|---|
| 관계명 | 두 엔터티가 맺는 업무의 동사 | 양쪽에서 읽을 수 있어야 한다 |
| 관계 차수 | 1:1 1:M M:N | M:N은 연결 엔터티로 풀어야 구현된다 |
| 선택성 | 필수(반드시 있다) 선택(없을 수도 있다) | 최소 참여를 정한다 |

- 식별 관계는 부모의 PK가 자식의 PK 일부가 되는 관계이고 비식별 관계는 부모의 PK가 자식의 일반 속성(FK)이 되는 관계이다.
- 비식별 관계에서 부모가 반드시 있어야 하면 FK에 NOT NULL을 지정하고 없을 수도 있으면 NULL을 허용한다.

### 5. 식별자

주식별자는 인스턴스를 구분하는 대표 속성이며 다음 네 가지를 만족해야 한다.

| 특징 | 뜻 |
|---|---|
| 유일성 | 값이 인스턴스마다 다르다 |
| 최소성 | 꼭 필요한 최소한의 속성으로 구성한다 |
| 불변성 | 한 번 정해지면 값이 바뀌지 않는다 |
| 존재성 | 값이 반드시 있다. NULL이 없다 |

식별자는 대표성(주식별자와 보조식별자) 스스로 생성했는지(내부 식별자와 외부 식별자) 속성 수(단일과 복합) 대체 여부(본질 식별자와 인조 식별자)로 나눈다.

### 6. 슈퍼타입과 서브타입

공통 속성을 가진 상위 엔터티(슈퍼타입)와 고유 속성을 가진 하위 엔터티(서브타입)를 물리 테이블로 바꾸는 방법은 세 가지다.

| 방식 | 구조 | 알맞은 경우 |
|---|---|---|
| 슈퍼타입과 서브타입을 모두 테이블로 | 1:1 관계의 테이블 여러 개 | 서브타입마다 조회가 많고 구분이 분명할 때 |
| 서브타입만 테이블로 | 공통 속성을 각 서브타입에 복사 | 서브타입별로 따로 처리할 때 |
| 슈퍼타입 하나의 테이블로 | 모든 속성을 한 테이블에 두고 구분 열을 추가 | 서브타입 차이가 작고 전체를 함께 조회할 때 |

### 자주 틀리는 포인트

1. 한 건뿐인 정보를 엔터티로 만든다.
2. 파생 속성도 반드시 저장해야 한다고 생각한다.
3. 식별 관계와 비식별 관계를 선의 모양만으로 구분한다. 기준은 부모 PK가 자식 PK에 포함되는지다.
4. 주식별자가 시간이 지나면 바뀌어도 된다고 본다. 불변성이 필요하다.
5. 개념 스키마와 내부 스키마의 역할을 바꿔 외운다.

### 복습 질문

1. 엔터티가 갖춰야 할 조건 가운데 인스턴스 수와 관련된 것은 무엇인가?
   답: 인스턴스가 두 개 이상 있어야 한다. 한 건뿐인 정보는 속성으로 보는 편이 맞다.
2. 부모 PK가 자식 PK에 포함되는 관계는 식별 관계인가 비식별 관계인가?
   답: 식별 관계이다. 부모 PK가 자식의 일반 속성이면 비식별 관계이다.
3. 한 사람이 전화번호를 여러 개 가질 때 모델링은 어떻게 하는가?
   답: 다중값 속성이므로 전화번호 엔터티를 따로 만들고 사람과 1:M 관계로 연결한다.

## Part 2. 모델과 SQL의 연결

### 1. 정규화

정규화는 중복을 줄이고 이상(입력 수정 삭제할 때의 오류)을 막으려고 테이블을 분해하는 과정이다.

| 정규형 | 조건 | 위반 예 |
|---|---|---|
| 제1정규형 | 모든 속성이 원자값이다 | 한 칸에 전화번호 두 개 |
| 제2정규형 | 기본키 일부에 종속된 속성(부분 종속)이 없다 | 복합키 중 상품번호만으로 상품명이 정해진다 |
| 제3정규형 | 키가 아닌 속성을 거쳐 결정되는 속성(이행 종속)이 없다 | 사원번호가 부서번호를 정하고 부서번호가 부서명을 정한다 |
| BCNF | 모든 결정자가 후보키이다 | 결정자가 후보키가 아닌 속성이 남아 있다 |

- 부분 종속은 기본키가 복합키일 때만 생길 수 있다. 기본키가 단일 속성이면 제2정규형은 자동으로 만족한다.
- 정규화하면 중복과 이상이 줄지만 조회 때 조인이 늘어난다.

### 2. 반정규화

성능을 높이려고 일부러 중복을 허용하는 작업이다.

| 기법 | 예 |
|---|---|
| 테이블 병합 | 1:1 관계의 두 테이블을 하나로 합친다 |
| 테이블 분할 | 열이나 행 단위로 나눈다 |
| 중복 열 추가 | 조인을 피하려고 자주 쓰는 값을 복사해 둔다 |
| 파생 열 추가 | 합계를 미리 계산해 저장한다 |

반정규화는 정규화를 마친 뒤 성능 문제가 확인되었을 때 검토한다. 중복된 값이 어긋나지 않게 갱신 규칙을 함께 정해야 한다.

### 3. 관계와 조인

- 엔터티 사이의 관계는 테이블에서 FK로 나타나고 조회할 때 조인으로 연결한다.
- FK가 있어야만 조인할 수 있는 것은 아니다. 값이 의미 있게 대응하면 FK 없이도 조인할 수 있다.
- 관계의 선택성은 조인 결과에 영향을 준다. 자식이 없을 수도 있는 부모를 모두 보려면 외부 조인이 필요하다.

### 4. 트랜잭션과 모델

- 트랜잭션은 하나의 업무 단위로 모두 성공하거나 모두 취소되어야 하는 작업 묶음이다. 성질은 원자성 일관성 격리성 지속성이다.
- 모델링에서는 한 업무가 여러 엔터티를 함께 바꾸는지 확인한다. 주문 등록이 주문과 주문 상세와 재고를 함께 바꾸면 한 트랜잭션으로 묶어야 한다.

### 5. NULL의 성질

- NULL은 값이 없거나 알 수 없다는 표시이며 0이나 빈 문자열이 아니다.
- NULL과의 산술 연산 결과는 NULL이다.
- NULL과의 `=` 비교는 참도 거짓도 아닌 알 수 없음(UNKNOWN)이 되어 `WHERE`에서 걸러진다.
- 집계 함수는 `COUNT(*)`를 제외하고 NULL을 무시한다.
- Oracle은 길이가 0인 문자열을 NULL로 취급하지만 SQL Server는 빈 문자열을 NULL과 구분한다.

### 6. 본질 식별자와 인조 식별자

| 구분 | 뜻 | 장점 | 단점 |
|---|---|---|---|
| 본질 식별자 | 업무에서 원래 쓰는 값(주민번호 사번) | 의미가 분명하다 | 복합키가 되기 쉽고 값이 바뀔 수 있다 |
| 인조 식별자 | 번호처럼 인위로 만든 값 | 단일 속성이고 변하지 않는다 | 업무 의미가 없어 중복 데이터를 막지 못한다 |

인조 식별자만 두면 같은 업무 데이터가 중복 입력되어도 막지 못하므로 본질 식별자에 UNIQUE 제약을 함께 두는 설계가 흔하다.

### 자주 틀리는 포인트

1. 기본키가 단일 속성인 테이블에 부분 종속이 있다고 말한다.
2. 이행 종속을 부분 종속과 섞는다.
3. 정규화를 많이 할수록 항상 빠르다고 생각한다.
4. FK가 없으면 조인할 수 없다고 생각한다.
5. NULL이 0과 같다고 보고 집계 결과를 계산한다.

### 복습 질문

1. 기본키가 단일 속성인 테이블은 어느 정규형을 자동으로 만족하는가?
   답: 부분 종속이 생길 수 없으므로 제2정규형을 자동으로 만족한다.
2. 사원번호가 부서번호를 정하고 부서번호가 부서명을 정할 때 위반하는 정규형은?
   답: 이행 종속이므로 제3정규형을 위반한다.
3. NULL을 `=`로 비교하면 어떻게 되는가?
   답: 결과가 UNKNOWN이라 `WHERE`에서 행이 선택되지 않는다. NULL은 `IS NULL`로 찾는다.

## Part 3. SQL 기본

### 1. SELECT의 처리 순서

| 순서 | 절 | 역할 |
|---|---|---|
| 1 | FROM | 대상 테이블을 정한다 |
| 2 | WHERE | 행을 거른다 |
| 3 | GROUP BY | 행을 묶는다 |
| 4 | HAVING | 묶음을 거른다 |
| 5 | SELECT | 열과 식을 계산한다 |
| 6 | ORDER BY | 정렬한다 |

- `WHERE`에는 SELECT 별칭을 쓸 수 없다. `SELECT`보다 먼저 실행되기 때문이다. `ORDER BY`에서는 별칭을 쓸 수 있다.
- `DISTINCT`는 선택한 모든 열의 조합이 같은 행을 하나로 합친다.

### 2. WHERE의 조건

```sql
SELECT cust_name
FROM customer
WHERE grade IN ('GOLD', 'VIP')
  AND city LIKE '서%'
  AND joined BETWEEN DATE '2024-01-01' AND DATE '2024-12-31'
  AND phone IS NOT NULL;
```

- 논리 연산자의 우선순위는 `NOT` `AND` `OR` 순이다. 의도한 순서가 아니면 괄호를 쓴다.
- `BETWEEN a AND b`는 양 끝 값을 포함한다.
- `LIKE`에서 `%`는 0글자 이상 `_`는 한 글자를 뜻한다.
- `x NOT IN (1, NULL)`은 어떤 x에서도 참이 되지 않는다. 비교 중 UNKNOWN이 생기기 때문이다.

### 3. 문자 함수 비교

| 기능 | Oracle | SQL Server |
|---|---|---|
| 일부 잘라내기 | `SUBSTR(s, 시작, 길이)` | `SUBSTRING(s, 시작, 길이)` |
| 글자 수 | `LENGTH(s)` | `LEN(s)` (뒤쪽 공백은 세지 않는다) |
| 위치 찾기 | `INSTR(s, 찾을값)` | `CHARINDEX(찾을값, s)` |
| 앞뒤 공백 제거 | `TRIM(s)` | `TRIM(s)` (최근 버전) |
| 바꾸기 | `REPLACE(s, 찾을값, 바꿀값)` | `REPLACE(s, 찾을값, 바꿀값)` |

- 문자열 연결은 Oracle이 `||` 연산자와 `CONCAT`을 쓰고 SQL Server가 `+` 연산자와 `CONCAT`을 쓴다.
- 시작 위치는 1부터 센다. Oracle의 `SUBSTR`에서 음수 시작 위치는 끝에서부터 센다.
- 연결 연산에서 NULL은 DBMS마다 다르다. Oracle의 `||`는 NULL을 빈 문자열처럼 다루고 SQL Server의 `+`는 결과가 NULL이 된다(기본 설정). SQL Server의 `CONCAT` 함수는 NULL을 빈 문자열로 다룬다.

### 4. 숫자와 날짜와 변환

- `ROUND(x, n)`은 소수 n자리로 반올림하고 n이 음수이면 정수 자리에서 반올림한다. Oracle의 `TRUNC(x, n)`은 버림이다. SQL Server는 `ROUND(x, n, 1)`로 버리거나 `FLOOR`와 `CEILING`을 쓴다.
- Oracle은 날짜에 숫자를 더하면 일 수만큼 더한 날짜가 된다. SQL Server는 `DATEADD(day, n, d)`를 쓴다.
- 형 변환은 Oracle이 `TO_CHAR` `TO_NUMBER` `TO_DATE`를 쓰고 SQL Server는 `CAST`와 `CONVERT`를 쓴다.
- 암시적 형 변환은 조건 열에 일어나면 인덱스를 쓰지 못하게 할 수 있다.

### 5. NULL 처리와 조건식

| 기능 | Oracle | SQL Server |
|---|---|---|
| NULL이면 대체 | `NVL(a, b)` | `ISNULL(a, b)` |
| NULL이 아니면 값1 | `NVL2(a, x, y)` | 없음. `CASE`로 쓴다 |
| 같으면 NULL | `NULLIF(a, b)` | `NULLIF(a, b)` |
| 처음 NULL 아닌 값 | `COALESCE(a, b, c)` | `COALESCE(a, b, c)` |
| 값 매핑 | `DECODE(a, v1, r1, 기본)` | 없음. `CASE`를 쓴다 |

```sql
SELECT order_no,
       CASE WHEN qty >= 10 THEN '대량'
            WHEN qty >= 5  THEN '보통'
            ELSE '소량' END AS size_type
FROM shop_order;
```

- `CASE`는 위에서부터 처음 참인 조건의 결과를 반환하고 이후 조건은 보지 않는다. `ELSE`가 없으면 맞는 조건이 없을 때 NULL이다.
- Oracle `DECODE`는 `=` 비교만 하지만 NULL끼리의 비교를 참으로 취급한다.

### 6. 그룹 함수와 GROUP BY

- 그룹 함수는 `COUNT` `SUM` `AVG` `MAX` `MIN` 등이다. `COUNT(*)`는 모든 행을, `COUNT(열)`은 그 열이 NULL이 아닌 행을 센다.
- `GROUP BY`를 쓰면 `SELECT`에는 그룹 기준 열과 그룹 함수만 쓸 수 있다.
- 집계 결과로 걸러내는 조건은 `HAVING`에 쓴다. 개별 행을 거르는 조건은 `WHERE`가 더 효율적이다.
- 모든 값이 NULL인 열의 `SUM`과 `AVG`는 0이 아니라 NULL이다.

### 7. ORDER BY

- 기본은 오름차순(`ASC`)이다. 여러 열을 쓰면 앞의 열이 같을 때 다음 열로 정렬한다.
- NULL의 위치는 DBMS마다 다르다. Oracle은 NULL을 가장 큰 값으로 보아 오름차순에서 마지막이고 `NULLS FIRST`와 `NULLS LAST`로 바꿀 수 있다. SQL Server는 NULL을 가장 작은 값으로 보아 오름차순에서 처음이다.
- 정렬 기준이 같은 행끼리의 순서는 보장되지 않으므로 순서를 정하려면 기준 열을 더한다.

### 자주 틀리는 포인트

1. `WHERE`에서 SELECT 별칭을 쓴다.
2. `COUNT(열)`이 NULL도 센다고 생각한다.
3. `AND`와 `OR`가 섞인 조건에서 괄호 없이 읽는 순서를 잘못 잡는다.
4. 연결 연산이 NULL을 만나면 DBMS와 상관없이 결과가 같다고 생각한다.
5. Oracle의 빈 문자열을 NULL로 보지 않는다.

### 복습 질문

1. `WHERE`에서 SELECT의 별칭을 쓸 수 없는 이유는?
   답: `WHERE`가 `SELECT`보다 먼저 처리되어 별칭이 아직 만들어지지 않았기 때문이다.
2. `COUNT(*)`와 `COUNT(열)`의 차이는?
   답: `COUNT(*)`는 모든 행을 세고 `COUNT(열)`은 그 열이 NULL인 행을 제외한다.
3. 오름차순 정렬에서 NULL은 어디에 놓이는가?
   답: Oracle은 가장 큰 값으로 보아 마지막에 놓이고 SQL Server는 가장 작은 값으로 보아 처음에 놓인다.

## Part 4. 조인

### 1. 조인의 종류

| 종류 | 설명 | 결과 |
|---|---|---|
| 내부 조인 | 조건이 맞는 행끼리만 결합 | 짝 없는 행은 빠진다 |
| 외부 조인 | 기준 쪽 행은 짝이 없어도 남기고 반대쪽은 NULL | LEFT RIGHT FULL |
| 교차 조인 | 두 테이블의 모든 조합 | 행 수는 두 테이블 행 수의 곱 |
| 셀프 조인 | 같은 테이블을 별칭으로 둘로 보고 결합 | 계층이나 비교에 쓴다 |
| 비등가 조인 | `=`가 아닌 범위 조건으로 결합 | 등급표와의 결합 등 |

```sql
SELECT o.order_no, c.cust_name
FROM shop_order o
INNER JOIN customer c ON o.cust_id = c.cust_id;
```

### 2. 표준 조인 문법

- `INNER JOIN ... ON 조건`은 조인 조건을 `ON`에 쓴다. 일반 필터는 `WHERE`에 쓴다.
- `JOIN ... USING (열)`은 이름이 같은 열을 지정하고 결과에 그 열이 한 번만 나온다. 이 열에는 테이블 별칭을 붙일 수 없다. USING은 Oracle 문법이며 SQL Server에는 없다.
- `NATURAL JOIN`은 이름이 같은 모든 열로 자동 조인한다. 같은 이름이 늘면 결과가 달라질 수 있다. SQL Server에는 없다.
- `CROSS JOIN`은 조건 없이 모든 조합을 만든다. 조인 조건이 빠진 쉼표 조인도 같은 결과가 된다.

### 3. 외부 조인

```sql
SELECT c.cust_name, o.order_no
FROM customer c
LEFT OUTER JOIN shop_order o ON o.cust_id = c.cust_id;
```

- 위 쿼리는 주문이 없는 고객도 `order_no`가 NULL인 행으로 남긴다.
- 외부 조인에서 반대쪽 테이블의 조건을 `WHERE`에 쓰면 NULL 행이 걸러져 내부 조인과 같은 결과가 된다. 반대쪽 조건을 유지하며 외부 조인을 하려면 `ON`에 쓴다.
- Oracle은 `WHERE a.k = b.k(+)`처럼 `(+)`를 짝이 없을 수 있는 쪽에 붙이는 옛 문법도 있다. 이때 `(+)`가 붙은 쪽이 NULL로 채워진다. SQL Server에는 없다.
- `FULL OUTER JOIN`은 양쪽의 짝 없는 행을 모두 남긴다.

### 4. 조인 결과의 행 수

- 조인 키 값이 중복되면 결과 행 수는 대응하는 행의 곱으로 늘어난다. 왼쪽 키 1이 두 행이고 오른쪽 키 1이 세 행이면 6행이다.
- 외부 조인은 내부 조인의 행에 짝이 없는 기준 쪽 행을 더한 것이다.
- 세 테이블 이상은 두 테이블씩 차례로 조인한다. 조인 조건이 n-1개 이상이어야 곱셈 폭발이 생기지 않는다.

### 자주 틀리는 포인트

1. 외부 조인의 반대쪽 조건을 `WHERE`에 써서 외부 조인이 풀린다.
2. 조인 키 중복을 고려하지 않고 행 수를 센다.
3. `USING`이나 `NATURAL JOIN`에서 공통 열에 테이블 별칭을 붙인다.
4. `(+)`가 붙는 쪽을 반대로 읽는다.

### 복습 질문

1. LEFT OUTER JOIN에서 오른쪽 테이블의 조건을 `WHERE`에 쓰면 어떻게 되는가?
   답: 오른쪽이 NULL인 행이 걸러져 사실상 내부 조인이 된다. 외부 조인을 유지하려면 조건을 `ON`에 쓴다.
2. 두 테이블의 키가 각각 2행과 3행으로 같은 값일 때 내부 조인 결과는 몇 행인가?
   답: 2 × 3 = 6행이다.
3. 교차 조인의 행 수는?
   답: 두 테이블 행 수의 곱이다.

## Part 5. 서브쿼리와 집합 연산

### 1. 서브쿼리의 위치와 종류

| 위치 | 이름 | 특징 |
|---|---|---|
| SELECT 절 | 스칼라 서브쿼리 | 한 행 한 열만 반환해야 한다 |
| FROM 절 | 인라인 뷰 | 결과를 임시 테이블처럼 쓴다. 별칭이 필요하다(SQL Server는 필수) |
| WHERE 절 | 중첩 서브쿼리 | 단일 행과 다중 행으로 나뉜다 |

- 단일 행 서브쿼리는 `=` `>` `<` 같은 연산자와 함께 쓴다. 결과가 여러 행이면 오류가 난다.
- 다중 행 서브쿼리는 `IN` `ANY` `ALL` `EXISTS`와 함께 쓴다.

### 2. 다중 행 연산자

| 연산자 | 뜻 |
|---|---|
| `x IN (서브쿼리)` | 결과 중 하나와 같다 |
| `x > ANY (서브쿼리)` | 결과 중 가장 작은 값보다 크다 |
| `x > ALL (서브쿼리)` | 결과 중 가장 큰 값보다 크다 |
| `EXISTS (서브쿼리)` | 서브쿼리 결과 행이 하나라도 있다 |

- `ALL`은 비교할 값이 하나도 없으면 참이고 `ANY`는 거짓이다.
- `NOT IN`의 목록에 NULL이 하나라도 있으면 결과가 비어 버린다. 이럴 때는 `NOT EXISTS`가 안전하다.

### 3. 상관 서브쿼리

바깥 쿼리의 열을 서브쿼리가 참조하는 형태이다. 바깥 행마다 서브쿼리가 다시 계산된다.

```sql
SELECT s.staff_name
FROM staff s
WHERE s.salary > (SELECT AVG(x.salary)
                  FROM staff x
                  WHERE x.dept_id = s.dept_id);
```

- 위 쿼리는 자기 부서의 평균보다 급여가 높은 직원을 고른다. 전체 평균과 비교하는 쿼리와 결과가 다르다.
- `EXISTS`는 행의 존재만 확인하므로 서브쿼리의 SELECT 목록은 결과에 영향을 주지 않는다.

### 4. 집합 연산자

| 연산자 | 결과 | 중복 |
|---|---|---|
| `UNION` | 합집합 | 제거한다 (결과 순서는 보장되지 않는다) |
| `UNION ALL` | 합집합 | 그대로 둔다 |
| `INTERSECT` | 교집합 | 제거한다 |
| `MINUS`(Oracle) 또는 `EXCEPT`(SQL Server) | 차집합 | 제거한다 |

- 연산 대상 SELECT는 열 개수가 같고 같은 위치의 자료형이 호환되어야 한다. 열 이름은 첫 번째 SELECT를 따른다.
- `ORDER BY`는 전체 결과에 대해 맨 끝에 한 번만 쓴다. 정렬 기준은 첫 번째 SELECT의 열 이름이나 위치 번호이다.
- Oracle은 전통적으로 차집합에 `MINUS`를 쓰고 SQL Server는 `EXCEPT`를 쓴다. 두 연산 모두 순서가 중요하다. A MINUS B와 B MINUS A는 다르다.

### 자주 틀리는 포인트

1. 단일 행 연산자로 여러 행을 반환하는 서브쿼리를 비교한다.
2. `NOT IN` 목록의 NULL을 고려하지 않는다.
3. 상관 서브쿼리를 한 번만 계산하는 것으로 본다.
4. `UNION`이 중복을 유지한다고 생각한다.
5. 집합 연산 중간에 `ORDER BY`를 쓴다.

### 복습 질문

1. `x > ALL (서브쿼리)`는 서브쿼리 결과의 무엇과 비교하는 것과 같은가?
   답: 결과 중 가장 큰 값과 비교하는 것과 같다. 결과가 비어 있으면 참이다.
2. `NOT IN`에 NULL이 섞이면 결과는?
   답: 어떤 행도 조건을 만족하지 못해 빈 결과가 된다. `NOT EXISTS`로 바꾸면 피할 수 있다.
3. `UNION`과 `UNION ALL`의 차이는?
   답: `UNION`은 중복을 제거하고 `UNION ALL`은 모든 행을 그대로 합친다. 둘 다 정렬 순서는 `ORDER BY` 없이는 보장되지 않는다.

## Part 6. 그룹 함수와 윈도우 함수

### 1. ROLLUP과 CUBE와 GROUPING SETS

판매 테이블의 지역과 상품별 합계를 예로 든다.

```sql
SELECT region, item, SUM(amount) AS total
FROM sales
GROUP BY ROLLUP (region, item);
```

| 구문 | 만들어지는 집계 단위 |
|---|---|
| `ROLLUP (a, b)` | (a, b) (a) 전체. 오른쪽부터 하나씩 줄이며 소계를 만든다 |
| `CUBE (a, b)` | (a, b) (a) (b) 전체. 모든 조합이다 |
| `GROUPING SETS ((a), (b))` | 지정한 단위만 만든다 |

- 소계 행에서 집계에서 빠진 열은 NULL로 나온다. 원래 NULL인 값과 구분하려면 `GROUPING(열)`을 쓴다. 그 열이 소계 때문에 비어 있으면 1이다.
- `ROLLUP`은 열의 순서가 중요하고 `CUBE`는 순서와 상관없이 같은 조합을 만든다.
- 열이 n개이면 `ROLLUP`은 n + 1가지 `CUBE`는 2의 n제곱 가지 단위를 만든다.

### 2. 윈도우 함수의 형태

```sql
SELECT staff_name, dept_id, salary,
       RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rk
FROM staff;
```

- `OVER` 안에서 `PARTITION BY`는 그룹을 나누고 `ORDER BY`는 그룹 안의 순서를 정한다. 행이 줄지 않는다는 점이 `GROUP BY`와 다르다.
- 윈도우 함수는 `SELECT`와 `ORDER BY`에만 쓸 수 있다.

### 3. 순위 함수

| 함수 | 동률 처리 | 값의 예 (동률 두 명이 1등) |
|---|---|---|
| `RANK` | 같은 순위를 주고 다음 순위를 건너뛴다 | 1 1 3 |
| `DENSE_RANK` | 같은 순위를 주고 건너뛰지 않는다 | 1 1 2 |
| `ROW_NUMBER` | 동률에도 항상 다른 번호를 준다 | 1 2 3 |

`ROW_NUMBER`에서 동률의 번호 순서는 `ORDER BY`에 기준 열을 더하지 않으면 정해지지 않는다.

### 4. 집계 윈도우 함수와 프레임

- `SUM(x) OVER (ORDER BY d)`는 정렬 기준 앞쪽 행부터 현재 행까지의 누적 합이다. 기본 프레임은 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`이므로 정렬 값이 같은 행은 모두 현재 행에 포함되어 같은 누적 값을 갖는다.
- 행 단위로 범위를 정하려면 `ROWS BETWEEN 1 PRECEDING AND CURRENT ROW`처럼 쓴다. 이동 평균에 쓴다.
- `ORDER BY` 없이 `OVER (PARTITION BY ...)`만 쓰면 파티션 전체가 대상이다.
- `LAST_VALUE`는 기본 프레임이 현재 행까지이므로 파티션의 마지막 값을 얻으려면 프레임을 `UNBOUNDED FOLLOWING`까지 넓혀야 한다.
- SQL Server의 `RANGE`는 `UNBOUNDED`와 `CURRENT ROW` 경계만 쓸 수 있다.

### 5. 앞뒤 행 참조와 비율 함수

| 함수 | 뜻 |
|---|---|
| `LAG(열, n, 기본값)` | 현재 행에서 n행 앞의 값 |
| `LEAD(열, n, 기본값)` | 현재 행에서 n행 뒤의 값 |
| `FIRST_VALUE` `LAST_VALUE` | 프레임의 처음과 마지막 값 |
| `NTILE(n)` | 파티션을 n개 구간으로 나눠 구간 번호를 부여 |
| `PERCENT_RANK` | (순위 - 1) / (행 수 - 1) |
| `CUME_DIST` | 현재 행 이하인 행의 비율 |
| `RATIO_TO_REPORT(열)` | 파티션 합계에 대한 비율. Oracle 전용 |

- `LAG`와 `LEAD`의 기본값을 지정하지 않으면 범위를 벗어난 행은 NULL이다.
- `PERCENT_RANK`는 행이 한 개뿐이면 0이고 `CUME_DIST`는 최소 1 / 행 수이다.

### 자주 틀리는 포인트

1. `RANK`와 `DENSE_RANK`의 동률 뒤 순위를 바꿔 쓴다.
2. 기본 프레임이 행 단위라고 생각해 동률 값의 누적 합을 틀리게 계산한다.
3. `ROLLUP`의 열 순서를 바꿔도 같은 소계가 나온다고 생각한다.
4. 소계의 NULL과 원래 NULL을 구분하지 않는다.
5. 윈도우 함수를 `WHERE`에 쓴다.

### 복습 질문

1. 1등이 두 명일 때 `RANK`의 다음 순위는?
   답: 3이다. `DENSE_RANK`는 2이다.
2. `GROUPING(열)`이 1이면 무슨 뜻인가?
   답: 그 열이 소계나 총계를 만드느라 집계에서 빠진 결과이다.
3. 윈도우 함수에서 `ORDER BY`를 쓰면 기본 프레임은?
   답: 처음부터 현재 행까지이며 정렬 값이 같은 행도 함께 포함하는 RANGE 방식이다.

## Part 7. Top N, 계층 질의, 셀프 조인

### 1. 상위 N개 행

| 목적 | Oracle | SQL Server |
|---|---|---|
| 상위 3행 | `FETCH FIRST 3 ROWS ONLY` | `SELECT TOP 3 ...` |
| 동점 포함 | `FETCH FIRST 3 ROWS WITH TIES` | `SELECT TOP 3 WITH TIES ...` |
| 건너뛰기 | `OFFSET 2 ROWS` | `OFFSET 2 ROWS FETCH NEXT 3 ROWS ONLY` |
| 옛 방식 | `ROWNUM` | 없음 |

- Oracle의 `ROWNUM`은 정렬하기 전에 행이 읽히는 순서대로 번호를 붙인다. 그래서 `WHERE ROWNUM <= 3`과 `ORDER BY`를 같은 쿼리에 쓰면 정렬된 상위 3행이 아니다. 정렬을 인라인 뷰 안에서 끝낸 뒤 바깥에서 `ROWNUM`을 건다.
- `ROWNUM = 1`은 첫 행을 반환하지만 `ROWNUM = 2`나 `ROWNUM > 1`은 항상 빈 결과이다. 번호는 반환이 확정된 행에만 붙기 때문이다.
- SQL Server의 `TOP ... WITH TIES`는 `ORDER BY`가 있어야 한다.
- 정렬 기준이 같은 행이 경계에 걸리면 어느 행이 포함될지는 정해지지 않는다. 확정하려면 기준 열을 더한다.

### 2. 계층 질의(Oracle)

부모와 자식이 한 테이블에 있는 조직도 같은 구조를 트리 순서로 읽는다.

```sql
SELECT LEVEL, staff_id, staff_name, mgr_id
FROM staff
START WITH mgr_id IS NULL
CONNECT BY PRIOR staff_id = mgr_id
ORDER SIBLINGS BY staff_name;
```

| 구문 | 뜻 |
|---|---|
| `START WITH` | 트리의 시작(루트) 행을 정하는 조건 |
| `CONNECT BY` | 부모와 자식을 잇는 조건 |
| `PRIOR` | 부모 행의 값을 가리킨다 |
| `LEVEL` | 루트가 1이고 내려갈수록 1씩 커지는 깊이 |
| `ORDER SIBLINGS BY` | 같은 부모를 가진 형제 사이의 정렬 |
| `SYS_CONNECT_BY_PATH(열, '/')` | 루트부터의 경로 문자열 |
| `CONNECT_BY_ROOT 열` | 루트 행의 값 |
| `CONNECT_BY_ISLEAF` | 더 이상 자식이 없으면 1 |

- `PRIOR staff_id = mgr_id`는 부모의 `staff_id`가 자식의 `mgr_id`와 같다는 뜻이므로 루트에서 아래로 내려가는 순방향이다. `PRIOR mgr_id = staff_id`로 바꾸면 자식에서 부모로 올라간다.
- `WHERE` 조건은 트리를 만든 뒤 행을 거른다. 하위 가지를 통째로 잘라내려면 `CONNECT BY`에 조건을 쓴다.
- 순환이 있으면 `NOCYCLE`을 쓴다.
- SQL Server에는 `CONNECT BY`가 없고 재귀 CTE(`WITH ... UNION ALL`)로 같은 일을 한다.

### 3. 셀프 조인으로 계층 보기

계층 질의를 쓸 수 없을 때는 같은 테이블을 별칭 둘로 조인해 한 단계씩 연결한다.

```sql
SELECT e.staff_name AS 직원, m.staff_name AS 상사
FROM staff e
LEFT OUTER JOIN staff m ON e.mgr_id = m.staff_id;
```

- 루트는 `mgr_id`가 NULL이라 `LEFT OUTER JOIN`을 써야 남는다.
- 단계가 정해지지 않은 깊이는 셀프 조인으로 한 번에 읽을 수 없다.

### 자주 틀리는 포인트

1. `ROWNUM`과 `ORDER BY`를 한 쿼리에 써서 정렬된 상위 N개라고 생각한다.
2. `ROWNUM > 1` 같은 조건이 결과를 낸다고 생각한다.
3. `PRIOR`의 위치만 보고 방향을 외운다. 부모 행의 값을 읽는 쪽이 어디인지 따진다.
4. `WHERE`와 `CONNECT BY`의 조건이 같다고 본다.

### 복습 질문

1. `PRIOR staff_id = mgr_id`의 읽는 방향은?
   답: 부모의 `staff_id`를 자식의 `mgr_id`와 연결하므로 루트에서 자식 방향으로 내려가는 순방향이다.
2. Oracle에서 급여 상위 3명을 `ROWNUM`으로 구하려면?
   답: 급여 정렬을 인라인 뷰 안에서 먼저 하고 바깥 쿼리에서 `ROWNUM <= 3`으로 거른다.
3. `LEVEL`은 무엇을 나타내는가?
   답: 트리의 깊이이다. 루트가 1이다.

## Part 8. PIVOT, UNPIVOT, 정규 표현식

### 1. PIVOT

행으로 있는 값을 열로 돌린다.

```sql
-- Oracle
SELECT *
FROM (SELECT region, quarter, amount FROM sales)
PIVOT (SUM(amount) FOR quarter IN ('Q1' AS q1, 'Q2' AS q2));
```

```sql
-- SQL Server
SELECT region, [Q1], [Q2]
FROM (SELECT region, quarter, amount FROM sales) AS src
PIVOT (SUM(amount) FOR quarter IN ([Q1], [Q2])) AS p;
```

- 집계 함수가 꼭 필요하다. 같은 조합이 여러 행이면 집계되고 없으면 NULL이다.
- `FOR` 뒤의 열과 집계 대상 열은 피벗 대상에서 빠지고 나머지 열이 행의 기준이 된다.
- Oracle은 `IN` 목록의 값에 별칭을 붙일 수 있고 SQL Server는 열 이름을 대괄호로 쓰고 결과에 별칭이 필요하다.

### 2. UNPIVOT

열로 있는 값을 행으로 돌린다.

```sql
-- Oracle
SELECT region, quarter, amount
FROM sales_wide
UNPIVOT (amount FOR quarter IN (q1 AS 'Q1', q2 AS 'Q2'));
```

- 새로 만들 이름 두 개를 지정한다. 하나는 값을 담을 열(`amount`)이고 하나는 원래 열 이름을 담을 열(`quarter`)이다.
- 기본적으로 값이 NULL인 행은 결과에서 빠진다. Oracle은 `INCLUDE NULLS`로 남길 수 있다.
- UNPIVOT은 PIVOT의 정확한 역연산이 아니다. 집계로 합쳐진 값은 되돌릴 수 없다.

### 3. 정규 표현식(Oracle)

| 함수 | 하는 일 |
|---|---|
| `REGEXP_LIKE(s, 패턴)` | 패턴과 맞는지 판별한다. 조건절에 쓴다 |
| `REGEXP_SUBSTR(s, 패턴)` | 맞는 부분 문자열을 반환한다 |
| `REGEXP_INSTR(s, 패턴)` | 맞는 부분의 위치를 반환한다 |
| `REGEXP_REPLACE(s, 패턴, 바꿀값)` | 맞는 부분을 바꾼다 |
| `REGEXP_COUNT(s, 패턴)` | 맞는 횟수를 센다 |

| 메타문자 | 뜻 |
|---|---|
| `.` | 임의의 한 글자 |
| `*` `+` `?` | 0회 이상 1회 이상 0회 또는 1회 |
| `^` `$` | 문자열의 시작과 끝 |
| `[abc]` `[^abc]` | 나열한 글자 중 하나 나열한 글자를 제외한 하나 |
| `{n,m}` | n회 이상 m회 이하 |
| `( )` | 묶음 |

- 세로선 `|`는 또는을 뜻한다.
- SQL Server 2022까지는 정규 표현식 함수가 없고 `LIKE`의 단순한 패턴만 쓴다.

### 자주 틀리는 포인트

1. PIVOT에서 집계 함수를 빼먹는다.
2. UNPIVOT이 NULL 값 행도 항상 남긴다고 생각한다.
3. Oracle 문법을 SQL Server에 그대로 쓴다.
4. `REGEXP_LIKE`를 `SELECT` 목록에서 값을 돌려주는 함수로 쓴다. 조건 판별용이다.

### 복습 질문

1. PIVOT 구문에서 반드시 필요한 것은?
   답: 집계 함수와 `FOR` 뒤의 열과 피벗할 값의 `IN` 목록이다.
2. UNPIVOT은 값이 NULL인 열을 어떻게 다루는가?
   답: 기본적으로 해당 행을 결과에서 뺀다. Oracle은 `INCLUDE NULLS`로 남긴다.
3. 맞는 부분 문자열을 꺼내는 Oracle 정규식 함수는?
   답: `REGEXP_SUBSTR`이다.

## Part 9. 관리 구문

### 1. DML

| 문장 | 하는 일 |
|---|---|
| `INSERT` | 행을 추가한다 |
| `UPDATE` | 행의 값을 바꾼다. `WHERE`가 없으면 모든 행이다 |
| `DELETE` | 행을 지운다. `WHERE`가 없으면 모든 행이다 |
| `MERGE` | 조건에 맞으면 갱신하고 없으면 삽입한다 |

```sql
MERGE INTO stock t
USING incoming s ON (t.item_id = s.item_id)
WHEN MATCHED THEN UPDATE SET t.qty = t.qty + s.qty
WHEN NOT MATCHED THEN INSERT (item_id, qty) VALUES (s.item_id, s.qty);
```

- `INSERT`에서 열 목록을 생략하면 테이블의 열 순서대로 모든 열의 값을 줘야 한다.
- 위 `MERGE`는 Oracle 형식이다. SQL Server도 `MERGE`를 지원하지만 문장 끝에 세미콜론이 필요하다.

### 2. TCL

| 문장 | 뜻 |
|---|---|
| `COMMIT` | 변경을 확정한다 |
| `ROLLBACK` | 변경을 취소한다 |
| `SAVEPOINT 이름` | 중간 지점을 만든다 |
| `ROLLBACK TO 이름` | 그 지점까지만 취소한다 |

- Oracle은 DML을 실행하면 트랜잭션이 암묵적으로 시작되고 `COMMIT`이나 `ROLLBACK`까지 이어진다. DDL과 DCL은 실행 전후에 자동으로 커밋된다.
- SQL Server는 기본이 자동 커밋이라 문장마다 확정된다. 여러 문장을 묶으려면 `BEGIN TRANSACTION`으로 시작하고 `COMMIT TRANSACTION`이나 `ROLLBACK TRANSACTION`으로 끝낸다. DDL도 트랜잭션 안에서 되돌릴 수 있다.
- `SAVEPOINT`는 Oracle 문법이고 SQL Server는 `SAVE TRANSACTION 이름`을 쓴다.

### 3. DDL

| 문장 | 하는 일 |
|---|---|
| `CREATE` | 객체를 만든다 |
| `ALTER` | 구조를 바꾼다(열 추가 수정 삭제) |
| `DROP` | 객체를 지운다 |
| `TRUNCATE TABLE` | 모든 행을 빠르게 지우고 구조는 남긴다 |
| `RENAME` | 이름을 바꾼다(Oracle). SQL Server는 `sp_rename` |

| 구분 | DELETE | TRUNCATE | DROP |
|---|---|---|---|
| 종류 | DML | DDL | DDL |
| 지우는 대상 | 조건에 맞는 행 | 모든 행 | 테이블 전체(구조 포함) |
| Oracle에서 롤백 | 가능 | 불가능(자동 커밋) | 불가능 |
| SQL Server에서 롤백 | 가능 | 트랜잭션 안에서는 가능 | 트랜잭션 안에서는 가능 |

- 자료형 이름은 DBMS마다 다르다. Oracle은 `VARCHAR2` `NUMBER` `DATE`를 많이 쓰고 SQL Server는 `VARCHAR` `INT` `DATETIME`을 쓴다.
- `ALTER TABLE ... ADD`로 열을 추가하면 기존 행에는 NULL이 들어간다. `NOT NULL` 열은 기존 행이 있으면 기본값 없이 추가할 수 없다.

### 4. 제약조건

| 제약 | 뜻 |
|---|---|
| `PRIMARY KEY` | 행의 식별자. 유일하고 NULL이 없다 |
| `UNIQUE` | 값이 중복되지 않는다. Oracle은 NULL을 여러 개 허용하고 SQL Server는 NULL을 하나만 허용한다 |
| `NOT NULL` | NULL을 넣을 수 없다 |
| `CHECK` | 조건식을 만족해야 한다 |
| `FOREIGN KEY` | 부모 테이블의 PK나 UNIQUE 값만 가질 수 있다 |

- FK의 삭제 규칙은 기본이 삭제 거부이고 `ON DELETE CASCADE`는 자식 행도 함께 지우며 `ON DELETE SET NULL`은 자식의 FK를 NULL로 바꾼다.
- 자식이 참조하는 부모 행은 기본 규칙에서 지울 수 없다.

### 5. DCL

| 문장 | 하는 일 |
|---|---|
| `GRANT 권한 ON 객체 TO 사용자` | 권한을 부여한다 |
| `REVOKE 권한 ON 객체 FROM 사용자` | 권한을 회수한다 |

- `WITH GRANT OPTION`으로 받은 사용자는 그 권한을 다른 사용자에게 다시 줄 수 있다. 이런 권한을 회수할 때의 연쇄 규칙은 DBMS마다 다르다. Oracle의 객체 권한은 연쇄적으로 회수되고 SQL Server는 `CASCADE`를 지정해야 한다.
- 여러 사용자를 한 번에 관리하려고 롤(role)을 만들어 권한을 묶어 부여한다.

### 자주 틀리는 포인트

1. `TRUNCATE`가 어느 DBMS에서나 롤백된다고 생각한다.
2. `UPDATE`와 `DELETE`에서 `WHERE`가 없으면 아무 행도 바뀌지 않는다고 생각한다.
3. DDL이 트랜잭션에 영향을 주지 않는다고 본다. Oracle에서는 자동 커밋을 일으킨다.
4. `UNIQUE` 제약의 NULL 허용을 DBMS와 상관없이 같다고 본다.
5. 자식이 참조하는 부모 행을 기본 규칙에서 지울 수 있다고 생각한다.

### 복습 질문

1. Oracle에서 `TRUNCATE` 뒤에 `ROLLBACK`하면?
   답: `TRUNCATE`는 DDL이라 자동으로 커밋되어 `ROLLBACK`으로 되돌릴 수 없다.
2. FK에 `ON DELETE SET NULL`을 지정하고 부모 행을 지우면 자식 행은?
   답: 자식 행은 남고 FK 열의 값이 NULL로 바뀐다.
3. `MERGE`는 어떤 때 쓰는가?
   답: 조건에 맞는 행이 있으면 갱신하고 없으면 삽입하는 작업을 한 문장으로 할 때 쓴다.

## Part 10. 시험 직전 점검

### 1. DBMS 차이 한눈에 보기

| 항목 | Oracle | SQL Server |
|---|---|---|
| 문자열 연결 | 세로선 두 개 연산자 (NULL은 빈 문자열처럼) | `+` 연산자 (NULL이면 NULL) |
| 빈 문자열 | NULL로 취급 | NULL과 다름 |
| NULL 대체 | `NVL` | `ISNULL` |
| 상위 N행 | `FETCH FIRST` 또는 `ROWNUM` | `TOP` |
| 차집합 | `MINUS` | `EXCEPT` |
| 계층 질의 | `CONNECT BY` | 재귀 CTE |
| 오름차순의 NULL | 마지막 | 처음 |
| 정규식 | `REGEXP_*` | 2022까지 없음 |
| TRUNCATE 롤백 | 불가능 | 트랜잭션 안에서 가능 |
| 트랜잭션 시작 | 암묵적 | 자동 커밋이 기본 |

### 2. 문제를 풀 때의 점검 순서

1. 지문에 DBMS가 적혀 있는지 본다. 없으면 두 DBMS에서 같은 결과가 나는 문제이다.
2. SELECT의 처리 순서(`FROM` `WHERE` `GROUP BY` `HAVING` `SELECT` `ORDER BY`)대로 한 단계씩 행 수를 따라간다.
3. NULL이 있으면 비교 결과가 UNKNOWN이 되는 곳을 표시한다.
4. 조인은 키 중복에 따른 행 수를 먼저 계산한다.
5. 윈도우 함수는 파티션을 나누고 정렬한 뒤 프레임을 정한다.
6. 선택지가 비슷하면 숫자와 열 이름과 정렬 방향의 차이를 비교한다.

### 3. 시간 배분

- 90분에 50문항이므로 문항당 평균 1분 48초이다.
- 모델링 문항은 개념을 아는지가 갈리므로 짧게 풀고 SQL 결과 추적 문항에 시간을 더 쓴다.
- 모르는 문항은 표시하고 넘어간 뒤 마지막에 다시 푼다. 미응답은 0점이다.

### 4. 합격 기준 확인

- 문항당 2점이고 1과목은 10문항 20점 2과목은 40문항 80점으로 총점은 100점이다.
- 총점 60점 이상이고 과목마다 40% 미만이 없어야 한다. 40% 미만이면 과락이므로 1과목은 8점 미만(3문항 이하) 2과목은 32점 미만(15문항 이하)이 과락이다. 따라서 1과목은 4문항 이상 2과목은 16문항 이상 맞혀야 하며 전체로는 30문항 이상이다.
- 60점이어도 한 과목이 40% 미만이면 불합격이다. 반대로 한 과목을 만점 받아도 다른 과목이 과락이면 불합격이다.

### 5. 시험 진행 규칙

공식 시험 안내를 학습용으로 줄인 것이다. 회차마다 세부 시간과 절차가 달라질 수 있으므로 접수할 때 공지를 확인한다.

- 시험 시간은 90분이다. 시험이 시작된 뒤에는 입실할 수 없고 정해진 시간 전에는 퇴실할 수 없다.
- 종이 문제지와 OMR 답안지로 치르며 답안은 OCR로 판독해 채점한다. 판독이 안 되면 0점이 될 수 있으므로 지정된 필기구(검정색 컴퓨터용 사인펜이나 볼펜)로 정확히 표시한다.
- 수정테이프와 수정액은 쓸 수 없다. 답안지는 시험 종료 5분 전까지 새 것으로 바꿀 수 있다.
- 계산기를 쓸 수 없다. 행 수나 집계는 손으로 따라가는 연습이 필요하다.
- 휴대전화와 스마트워치 같은 전자통신기기는 사용하지 않아도 소지만으로 무효 사유가 될 수 있다. 시계는 아날로그 손목시계만 허용된다.
- 이 사이트의 120분과 시간 제한 없음은 연습용 선택이며 실제 시험 시간은 90분이다.
